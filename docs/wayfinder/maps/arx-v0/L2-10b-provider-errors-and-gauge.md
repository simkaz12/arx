# L2-10b — provider errors by continuation class, and the gauge

Cut from L2-10 on 2026-09-04 by main under the owner's overnight clearance; the second session, on top of L2-10a's loop.

## Deliverable

`ProviderError` grows from one variant to the three classes: `Transient { kind, retry_after }`, `Fatal { kind }`, `ContextWindowExceeded { overshoot }`. A stream wrapper around every adapter retries `Transient` (429, 5xx, a transport error) before the first item with the vendor's `retry-after` or a bounded backoff, and never after the first item. A 400 rejected before the first item is classified by the adapter: the OpenAI-compatible adapter parses "maximum context length is X ... resulted in Y" into the overshoot and returns `ContextWindowExceeded`, everything else stays `Fatal`. The gauge: occupancy is read from whatever usage shape the adapter returned — the Anthropic fields the reader sums today and the OpenAI-compatible `prompt_tokens` family it silently ignores — so a native hand's nudge can fire at all; and a per-model context window limit enters config as the operator's constant, so the gauge has a denominator and a `ContextWindowExceeded` on the wire tells the operator the constant may need updating. The continuation of `ContextWindowExceeded` for a hand (rewind-to-fit, state object, respawn) is L2-13's; here it surfaces as the verdict with the overshoot named and lands as a `miss` event carrying the size.

## Done when

A stubbed 429 followed by a 200 yields one verdict and two requests, with the retry before any chunk; a stubbed 503 mid-stream (after the first item) is not retried and surfaces as `Fatal`; a stubbed 400 with the vendor's context message surfaces as `ContextWindowExceeded` with the overshoot parsed and a `miss` event in the transcript log carrying the size; a 400 without numbers still classifies as `ContextWindowExceeded` with `overshoot: None`; `transcript::occupancy` returns the prompt token count for OpenAI-shaped usage and the existing sum for Anthropic-shaped usage, with the existing nudge tests unchanged; the window limit key parses, `check-config` output is byte-identical without it, and a native hand whose definition names a model with a limit reports occupancy against it in its verdict's usage line or the gauge; `L1-10`'s trait is unchanged.

## Shipped

`ProviderError` grew from one bare `Fatal(String)` into three classes on `provider.rs`: `Transient { kind, retry_after }`, `Fatal { kind }`, `ContextWindowExceeded { overshoot: Option<Overshoot> } }`, with `Display` rendering `transient (<kind>)`, `fatal: <kind>`, and `context window exceeded (requested N, maximum M)` or `(size unknown)`. Every `Fatal(String)` constructor and pattern across `provider.rs`, `openai_compat.rs`, `anthropic.rs`, and `native_hand.rs` moved to the struct shape. `Retrying<P: Provider>` wraps every adapter `build_provider` returns: a `Transient` from `complete` waits the vendor's `retry-after` or `500ms × 2^(attempt-1)`, polling the cancel flag every 50ms and failing `Fatal { kind: "killed" }` if it fires mid-wait, up to three calls total before the last `Transient` surfaces as-is; a stream that errors after its first item is never retried, since `Ok(stream)` passes through untouched.

The OpenAI-compatible adapter classifies before the first item: a transport error is `Transient { kind: "transport" }`; 429 and 5xx are `Transient` carrying the `Retry-After` header when present; a 400 whose body names `context_length_exceeded` or `maximum context length` is `ContextWindowExceeded`, with `parse_overshoot` reading the first integer after `maximum context length is` and after `requested` (falling back to `resulted in`), no regex crate; every other non-2xx stays `Fatal` with the same `HTTP <status> from <url>: <body>` text the adapter always built.
