# L2-14 — arx's own tools gated in the handler

## Deliverable

Every arx-served call on a Claude Code main crosses the sidecar pipe once. The sidecar lists its own registrations in the SDK's `allowedTools`, so `canUseTool` never fires for them; the Rust handlers for the store, hand and file events run arx's gate first, write the same `Event::Gate` row the gate path wrote, hold on the terminal for an `ask` with the same two-row shape and rule append, and on a deny return the reason to the model as the tool result without executing. `canUseTool` stays as the gate for tools the body itself owns. Born from the owner's question on the double crossing and the ruling that efficacy is a priority.

## Done when

On the stub sidecar, which no longer emits gate events for arx's own tools: a store, a hand and a file call each produce exactly one gate row, before their effect; a denied dispatch writes no spawn; a denied read writes no file row; every existing gate-row test, the L1-close script and the ask tests pass unchanged.
