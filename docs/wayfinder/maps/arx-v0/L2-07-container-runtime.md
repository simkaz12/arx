# L2-07 — container runtime and allowlist

## Deliverable

Every hand runs in a container arx controls, on the host's process tree: an allowlist that is empty by default — no host env, no home — a worktree per write-enabled hand, the store never mounted, the capture sweep run at teardown — a hand's trace, its worktree diff included, taken before the container and worktree are destroyed (`4f90f38f`) — and the spawn seam L1-07 uses pointed at the container instead of the host. Proven with L1-07's fake hand; the real bodies move in with L2-08, L2-09 and L2-11.

## Done when

A fake hand in a container sees no host environment variables and no home directory; a write-enabled hand gets its own worktree and its writes are visible there and nowhere else; a write-enabled hand is torn down and its work applies cleanly from the trace handle alone, worktree and container gone (`4f90f38f`); a hand's attempt to read the store path fails; the container is gone after kill; L1-07's done-check passes with the fake in a container.

## Shipped

A hand's container mounts off a hand root arx creates under the system temp dir (`<temp>/arx-hands/<hand>-<pid>-<nanos>/`, `home/` and `out/` always, `worktree/` only when write-enabled): the repository at `/hand/repo` — a detached `git worktree add --detach HEAD` for a write-enabled hand mounted read-write, the live tree itself mounted `readonly` for everyone else — an empty `/hand/home` and an `/hand/out`, the arx user's own uid:gid read from the hand root's own metadata, and an environment of the image's own vars plus `HOME=/hand/home` plus the definition's `env` allowlist copied from arx's environment name by name. When the store root sits under the repo's toplevel, an empty `--tmpfs <path>:ro` masks it on top of the repo mount for both mount kinds — the one deviation from the card's wording, which called only for "never mounted": a tracked copy in a worktree needs masking the same way the live directory does, verified against this repository's own tracked `store/` live on the host (`--tmpfs` over a path absent from the mount source fails the container at `docker run`, so the mount point must already exist — true for every real dispatch, since `Engine::open` creates `store/` before any dispatch can run).

At teardown — a clean exit, a crash, or a kill alike — the container thread sweeps before anything reaches main's window: `docker rm -f`, the worktree diff (`git add -A` then `diff --cached --binary HEAD`, write-enabled only), `trace.md`'s front matter (hand, agent, thread, image, container, exit — the status code or `killed` — write, base, and a `paths` list with byte counts) plus one body line, `out/` copied verbatim, then `git worktree remove --force` and the hand root removed. The handle is `threads/<thread>.<hand>`; `Delivery::Verdict` and `Delivery::Killed` both carry it plus the sweep's total bytes, and `Event::Delivered` carries the same two fields additively — `KINDS` stays at 17.

Kill diverges by body. The three host bodies keep `SpawnLedger::kill`'s synchronous row-and-push exactly as they were. `BodyKind::Fake` sends `Control::Kill` and returns without writing a row or pushing a delivery; `docker kill <name>` is retried every poll tick against a container-registration race a live probe surfaced (`docker kill` issued microseconds after `docker run --name` fails silently with "no such container" until the daemon catches up, which stranded a hand for its full delay before the fix). The `killed` row lands only once the thread's real `Delivery::Killed` is drained, carrying the trace. `SpawnLedger::in_flight` widened from "state is Running or Stopped" to "not yet terminally delivered": a container-killed hand is terminal to `is_eligible` at once, per the card, but still in flight until its own teardown actually completes, or `cmd_run`'s shutdown loop exits before the kill's sweep ever lands — caught live by `kill_removes_the_hand_and_injects_the_stub` exiting in 0.1s with no killed row, fixed, reverified.

Agent definitions gain three additive frontmatter keys — `write: bool`, `env: Vec<String>`, `image: Option<String>`, defaulting to not-write-enabled, no allowlist, `alpine:3.20` — carried through `RoleRow` and folded into `HandSpec`; `check-config`'s six columns diffed byte-identical against a scratch build of `main`. `fake` and `fake-write` are the two names the write axis rides on, no definition file, both `DEFAULT_HAND_IMAGE` with an empty allowlist. The fake is `fake_hand.sh`, a 69-line POSIX script embedded with `include_str!` and driven `sh -c <script> fake-hand <brief>`: `[delay:N]`, `[stop:<q>]`, `[verdict:<t>]`, steer-as-extras and `[crash]` mirror the deleted in-process closure; `[write:<path>=<text>]`, `[read:<path>]` and `[probe]` are new, the last reporting `env=`, `home=`, `home_entries=` and `cwd=` for the done-when's container proof.

Every ledger test that dispatches a fake hand without awaiting or killing it had its delay shortened from 5-60 seconds to 300ms: an in-process thread was reclaimed for free at test-process exit, a real `docker run` process is not, and cargo runs a binary's tests in parallel by default. One test races a wall-clock sleep against a container reaching its `[stop:]` point before steering early; its margin widened from 80ms to 8 seconds after 2 seconds flaked once under the workspace's full parallel load. `hands_in_containers.rs`'s five tests serialize on a mutex — Docker's name filter matches by substring, not anchor, and every fresh ledger restarts hand ids at `h1`, so two of these tests running concurrently could see each other's containers and fail on a phantom leak.

The live check ran on the owner's login against the real sidecar and Claude Code body, in a scratch repository with one commit: `fake` dispatched `[probe][write:note.txt=hi]` surfaced `env=HOME,HOSTNAME,PATH,PWD,SHLVL home=/hand/home home_entries=0 cwd=/hand/repo` in the verdict injection — `PWD`/`SHLVL` are the shell's own (`docker run --rm alpine:3.20 env`, no shell, gives exactly `HOME`, `HOSTNAME`, `PATH`), not a host leak — and the write failed inside the read-only mount, `Read-only file system` landing in `out/stderr.log`. `fake-write` dispatched the same brief; `git apply threads/main.h2/worktree.diff` by hand in the scratch repo produced `note.txt` reading `hi`, `git status --short` showing exactly that one new file. `docker ps -a --filter label=arx.hand` was empty and the scratch directory removed after both.

Two deviations from the card's literal signatures, both load-bearing. `container_hand::spawn_container_hand` takes a sixth parameter, the already-`prepare`d hand root and worktree base, because `SpawnLedger::dispatch` must know the container's `root` path before it writes the spawn row, and the fixed five-argument signature left no way to hand that same state into the spawned thread without computing a second, orphaned hand root under a fresh nonce. `container_hand::plan` takes `argv` as a parameter, matching the surrounding prose ("so L2-08 can pass `claude -p …`") over the signature line beside it, which omitted it; `ContainerSpec` also carries `hand` and `thread` fields the struct listing omitted but the container's own shape — `--label arx.hand=<hand> --label arx.thread=<thread>` — requires.

`crates/arx/tests/claude_main.rs` took no edit at all — none of the four L1-07 tests compares a verdict or killed injection by byte equality, only by prefix or substring, so the trace suffix the container path adds never needed the permitted widening. `tests/common/mod.rs` gained the git-init two-liner the card named plus `fresh_run_fixture_without_git`, needed by Scope 3's refusal test but not listed in that scope's own Files section; both land in the one file the brief let either scope touch.
