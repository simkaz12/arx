# D15 — The state object's missing check

> **Closed 2026-08-28** after one grill, three rounds — see Resolution. The banner below is kept for the record.
>
> **Next grill — owner pick 2026-08-28** (`map.md`, frontier note of the same date). Scope widened to the whole reset seam: D14's second bullet (the reset ritual's cost inside an already-over-budget window) and the map's "who fires a reset" fog item (harness on the token counter, or operator on a surfaced counter) are grilled here, not separately.

New ticket, opened from the two 2026-08-27 owner rulings (`749c8765`, `da0ccf24`) rather than from a research ticket — no T-series findings ground it, only the rulings themselves and the debate rows that named the gap before the rulings created it. The plans debate found the reset cross-validation broken while the observer still existed on paper: the delta a fold compares against is undefined everywhere, so the check was already comparing two derivatives of one pen (`S-RUNE-3`, plans, agreed, major), and the cross-validation defined no continuation on disagreement, so it controlled nothing even when it ran (`S-SOL-8`, plans, agreed, major). Dropping the observer did not repair either finding — it removed the second party both findings were about. The next-steps debate named the result directly, at blocker severity: dropping the observer and the digest together removes both counterparties from the reset check, leaving main to author and truth-check its own sole continuity artifact, with no replacement check written anywhere (`S-RUNE-1`, next-steps, agreed, blocker). `749c8765`'s own text records the same thing as a live consequence, not yet closed: "the main now authors and truth-checks its own only continuity artifact with no independent check written anywhere, and the probe's trigger, already open before this, is the only remaining candidate for one."

## Question

How does the state object get an independent check now that the party who writes it is the same party who validates it? Nobody has proposed an answer. The rulings that created the gap name it as open rather than close it, and the three ledger rows above only establish that the design's prior check — the observer's cross-validation — never actually worked before it was removed.

Two questions the CONTEXT.md reconciliation pass surfaced sit inside the same territory and could not be settled there, because they are not separable from this one:

- **The probe's trigger.** The probe's standing argument for running periodically rather than only at reset was that a fold accumulates error — a wrong state at step 3 is inherited by every later state, so one check at the end catches it at maximum cost and minimum recoverability (`ab0077b4`, carried forward by `e5bc73d5`). Nothing folds now: the main writes the state object once, at reset, rather than an observer maintaining it as a running fold. The argument has no subject to accumulate error in, and no replacement argument for periodic-versus-reset-time is stated anywhere in the store. Meanwhile `749c8765` makes the probe the only remaining candidate for the missing check at all, which raises the trigger question's stakes without answering it: whatever runs, and whenever it runs, is now the whole of the independent-check apparatus, not one layer of several.
- **Per-entry provenance.** The state object's entries used to carry an anchor naming the turn or step they folded from — one of the two mitigations `f478d4bc` (superseded 2026-08-27 by `1154bf53`) recorded as still bounding fold drift after the ninth-session trim, auditable at one hop, cheap to verify at read time. With no fold, there is nothing for an entry to name a turn as folded *from*; the mechanism's own description no longer parses against how the state object gets written. Whether per-entry provenance survives in some other form — an entry naming the reset it was authored at, say, rather than a fold it never underwent — or whether it lapses along with the fold it was built for, is unruled.

A probe tests sufficiency — whether a fresh context could resume the work from the state object alone — and structurally cannot catch falsehoods: a state object can read as complete and internally consistent while asserting something that did not happen, and a dispatch checking only whether it could resume from that text has no independent way to notice. State that as the difficulty this ticket has to design around, not as a reason to rule the probe out or in. `749c8765` names the probe "the only remaining candidate" for an independent check precisely because the main's own truth-check is the only check of the *other* kind — catching falsehoods, not sufficiency — and no third party is left to run the complementary one.

## Resolution

One grill, three rounds, eight rulings, no debate — the grounding was the debate ledgers themselves. The reset seam whole, as scoped on 2026-08-28:

- **Who fires, and whether an exhausted window can afford it** (the fog item and D14's second bullet) are one knob. Authoring needs the window as input plus room for output, so a reset fires against a reserve below the hard limit, sized to the ritual: the harness arms at limit-minus-reserve and tells the operator, the operator fires, and the harness fires alone only at the reserve's floor, so an unattended thread never dies without a state object (`d65f8fe1`). A window already past the reserve rewinds to fit first — mechanical cut-to-archive, no model call — then runs the ritual; that is the sequencing artifact `S-RUNE-9` found missing (`e2b0ceb2`).
- **The ritual** is an authoring turn, a separate harness-prompted truth-check turn, a mechanical check on every write (file exists, decision id resolves, sha still matches — carried from `ab0077b4`, where it bound observer writes), and an operator surface: shown before teardown and amendable when attended, shown at next contact when not (`18fec68a`).
- **The missing check** resolves into three checks of different kinds rather than a second model pen: the mechanical check for what a machine can verify, the operator surface for truth, and the respawned main's own first turn — a mandated orientation report — for sufficiency. The probe *is* that first turn, not a separate dispatch, which closes its trigger question: it fires at every respawn, and periodic is dead for a blunter reason than the fold's absence — an unread checkpoint needs no sufficiency check, and the one that is read gets it from its reader (`253334ad`). The pre-teardown hand was rejected: it guards a source that survives on disk anyway.
- **The falsehood residual** is accepted and named: a complete, consistent, wrong judgment claim is caught by the operator or nobody. It becomes a D09 signal — the respawned main discovering the object was wrong rather than thin is countable, self-reported at the seam (`b03f77fc`). A second model pen was rejected on `S-RUNE-3`'s own ground: nobody but main holds ground truth, so a second reader of the same window only re-derives.
- **Checkpoints** — owner ruling against the round-2 recommendation, and the recommendation was the flaw. Reset-only authoring has no recovery for exhaustion, the common death, because the transcript that killed the window cannot fit in the fresh one, while a small recent checkpoint can. Main authors the state object on a token-delta clock between turns, never mid-dispatch, full ritual each time (a wrong checkpoint is worse than none), and the harness rewinds the checkpoint turns out of the window afterwards so the object does not spend the budget it protects (`2c198c9f`, superseding `4833a3a3` on lifecycle only). No derivative chain forms — each checkpoint is authored from the window, never from the previous object — so `S-RUNE-3` does not recur. Named override of POSITION §6 q4's manual-first readiness test; cadence-off is the manual path.
- **Provenance** is header-level — checkpoint ordinal, timestamp, `(thread, turn)` handle — and the object is authored fresh each time, the prior object being orientation input rather than template (`18b4928b`). Per-entry turn anchors lapse; the only per-entry provenance is what the mechanical check already needs.
- **Look-back handles**, owner addition in round 2. The harness mints `(thread, turn)` handles mechanically on every store save from main, every checkpoint and the state object's header, filling D13's claim handle field (`7be68c4a`) with a pointer into the context that minted the claim. This needs a per-thread append-only transcript log independent of rewind — the third persisted file beside the state object and the spawn ledger (`eff1f01a`, superseding `ba6fd355`). Turn grain; machine-local in v1, since the store syncs by git and thread logs do not, and an unresolvable handle leaves the claim standing.

Vocabulary in `CONTEXT.md`: Reset, Probe, State object and Handle rewritten; Checkpoint and Transcript log added.

Ticket impact: **D14** shrinks to its `ContextWindowExceeded` bullet, as the 2026-08-28 frontier note already said. **D09** gains one signal — the state-object-wrong event. **D04**'s persistence ruling grows by one file. The "who fires a reset" fog item closes.
