# D16 — Bodies per role

> **Closed 2026-08-30** after one grill across two days, four rounds, fourteen questions, fourteen rulings; sol silent on rounds 1 and 2, skipped on 3 and 4 (prompt over the 40k cap once CONTEXT.md plus the grill's decisions were in it). The charter's premise fell in round 1: the owner does not want Claude Code as the host at all. See Resolution.

## Question

Owner ruling in the D06 session, 2026-08-29 (`568f864d`): the daily shape is Claude Code CLI as the deciding loop the owner thinks and plans in, arx supplying the hands, and Codex CLI as the cross-model judge — and each of the three roles (main, hand, judge) must be configurable as to which model and/or which CLI fills it. "For flexibility i need to be able to configure what model and/or cli is used for main, hands or cross model judge (like now codex is)." *(568f864d itself is retired 2026-08-30 by `890ebff2`, which keeps this configurable-roles clause as the D16 seam below and drops the hands-service/CC-as-loop framing the charter read it through.)*

That lands against four in-force rulings: `7d1f7da4` (the participant set is arx's main plus its hands), `41bf6e4f` and `0be93430` (a model behind a CLI enters only as a hand, never as main), and `ca15f9eb` (main does not run Fable on current access terms, because the sanctioned subscription routes surrender the window). The owner now accepts the surrendered window for main. `CONTEXT.md` carries the terms provisionally — Body, Judge, and Main amended to "a role filled by a body" — pending this ticket. To settle:

- **The seam.** Is the deciding loop a seam with two adapters — arx's native loop over a provider, and a CLI body driven as a process — and what interface does arx present to a CLI-bodied main: an MCP server exposing dispatch / tap / steer / kill, a CLI, or both? t3code's adapter SPI (`findings/t3code-claude-embedding.md`) is the field's answer for driving both CLIs from one host.
- **What survives under a CLI-bodied main.** State object, checkpoint, reset, nudge, reserve, quarantine, drain, claim minting, transcript log — every one is main-authored. Which move to the CLI's own machinery (Claude Code's compaction, its memory), which arx still runs as a service beside the CLI (the transcript log and spawn ledger are harness-written and could), and which simply do not run. The store's "claims are minted only by main" clause needs a minter when main is Claude Code.
- **The supersessions.** Which clauses of `7d1f7da4` / `41bf6e4f` / `0be93430` / `ca15f9eb` fall and which stand. `41bf6e4f`'s "never as main's provider" is still literally true — a CLI is a body, not a provider — so the cut may be narrower than the four ids suggest. `ca15f9eb` carried named reopen triggers; check whether this is one.
- **The judge as a role.** Today the drain's judge is "a dispatched hand of a different model family" (`27e7cea9`) and the gauntlet's critics; the parked multi-provider critic-seat capability (`9def5cea`) lives here too. Is judge a hand under a constraint — different family from main, no write — or a third role with its own configuration? A Codex body brings its own approval and sandbox modes (`296676f6`: `sandbox_mode` read-only | workspace-write), which is the D06 gate's foreign-body case again.
- **Configuration shape.** Per role: body kind (native | claude-code | codex | …), model, and for a native body a provider. Where it lives — startup config, per `f5b5caf4` — and whether a role's body can vary per dispatch (hands already do, through the named agent definition) or is fixed per harness run (main).
- **What the window costs.** `ca15f9eb` refused the subscription routes because they surrender the window. Name what arx gives up on main under a Claude Code body — admission on main's tool results, arx's gate on main (Claude Code's runs instead), the nudge and the reserve — and confirm the hand side keeps everything: gate, containers, worktrees, traces, capture surface, the spawn ledger.

**Gained from D12 (2026-08-29, closed):** a Claude-Code-bodied hand gets store context by push alone in v1 — grounding as text in its brief — because reaching arx's store mid-loop from inside Claude Code means arx exposing an MCP surface (`e79bed85`). Whether that surface exists, and whether it is the same one a Claude-Code-bodied main would use for dispatch / tap / steer / kill, belongs to the seam bullet above.

## Resolution

One grill, four rounds. The ticket was chartered on the owner's D06 phrase "think/plan with cc cli and have arx as hands", and the interviewer's round-1 recommendation followed it literally: Claude Code interactive as the host, arx entering as an MCP server. The owner refused that reading — "arx should be the main, not cc. we are making harness for a reason and i want the main, hands and judges to be swapable, may it be cli or provider" — and every later ruling follows from that one. Two source traces were dispatched mid-grill: the Claude Agent SDK's switches (autocompact off, per-message usage, `disallowedTools: ["*"]`, `interrupt()` on the continuous client, from the official docs) and Codex CLI's drive surfaces (`findings/codex-cli-drive-surfaces.md`, two traces of openai/codex).

- **The seam** (`705e4df2`, `e652ce3a`). arx hosts main under every body: it owns the operator surface and the process tree, and a CLI body is a child arx drives, never a host that reaches arx over MCP. The deciding loop is a real seam with two production adapters, arx's native loop over a provider and a CLI driven as a child. One adapter per CLI kind, role-agnostic — the role decides what arx mounts into the child (main: dispatch / tap / steer / kill plus save and drain; hand: grounding pushed as text) and where ask lands. Bare `claude -p` and `codex exec` have no approval callback, so they are hand-only; a CLI main runs over the Agent SDK or Codex's app-server JSON-RPC. Rejected: Claude Code as host with arx an MCP server — it inverts the harness.
- **What survives** (`952d3b69`, `7b607c7e`, `e4510547`). arx's reset apparatus binds every body; rewind is the one native-only mechanic. arx reads usage from the child's stream, so nudge and reserve run as native; reset is kill-and-respawn with the state object as orientation; a window past the reserve resets without rewind-to-fit, and a checkpoint's ritual turns stay in the window. The reserve arms below the body's compaction threshold, which arx pushes above its own hard limit (Claude Code: `autoCompactEnabled: false`; Codex: `model_auto_compact_token_limit`, no off switch) — owner: "the codex should not even get to compact". Main's transcript log is arx-written from the child's stream, so a claim's trace handle is body-independent and the body's own session file is never read. Owner on the cost: "what i cant change is the controll on cc and codex. thats the price that i have to pay until there is some model from a provider that is usefull and with reasonable price." *(The exhaustion floor this survival lacked is ruled 2026-08-30 — `31a20ff6`.)*
- **The supersessions** (`96ce60c0` supersedes "a CC-bodied Fable is a hand, never main's provider"; `c8ef1d51` supersedes "main does not run Fable under current access terms"). The first loses its hand-only half — a CC-bodied Fable may fill main — and keeps "never as main's *provider*" literally true. The second narrows to arx's *native* main; a CC body runs Fable as main with the window surrendered by choice; none of its reopen triggers fired, and they now govern only a native Fable main. "arx's participant set is main plus its hands" and "no capability flags on the provider trait" stand unchanged. *(Corrected 2026-08-30 by `975f65cd`: the no-capability-flags clause still stands, but `0be93430`'s hand-only clause — a model behind a CLI enters as a hand, never as main — does not; a model behind a CLI enters as a body through the D16 seam, in any role.)*
- **The judge as a role** (`1e6ad121`, `da3f5418`). A role in config, a hand at runtime: a dispatch under the reserved agent definition `judge`, read-only clamp, no save verb, no third lifetime class. Different family from main is checked at dispatch and logged as a warning, never refused. The return is an arx-defined verdict schema, filled through `codex exec --output-schema` or the SDK's structured output; Codex's `review/start` (own rubric, own `review_model`, fixed findings shape a host cannot replace) is not used. Owner: "i feel like the judge should be a seperate, but for now lets go with a" — a third participant is the named reopen. The parked critic-seat capability lands here.
- **Configuration shape** (`0bd4df2f`). Per role: `body` (native | claude-code | codex), `model`, and for a native body a `provider`. Main's block is startup config, fixed per run; a hand's is its agent definition; the judge's is the `judge` definition. The drive surface is never configured, it follows from the role. Owner: "agreed, for now."
- **The gate across bodies** (`64c789d0`, `70260cad`). The gate's interface stays allow / deny / ask; adapters narrow the body's richer answers (Codex's `acceptForSession` and policy amendments, the SDK's permission updates) and never widen them. Main's tool surface is arx-owned wherever the body permits: Claude Code strips its built-ins and runs on mounted tools; Codex cannot, so its own tools run under arx's gate through the approval callback with admission covering mounted tools only, logged as a degradation. Rejected: barring a Codex main.
- **Instructions** (`68c366dc`, `ceb0390f`). arx's own system prompt replaces the body's built-in instructions on both CLIs (SDK `systemPrompt`; Codex `baseInstructions` on `thread/start`, `-c instructions=` under `exec`), new-thread-only, which fits kill-and-respawn. arx suppresses the body's discovery of CLAUDE.md / AGENTS.md and pushes the repo file itself when the agent definition says so, so the transcript log records what the model saw.
- **What the window costs**, confirmed as the record. Under a CLI main arx gives up rewind (checkpoints cost window room, reset has no rewind-to-fit), request construction and context assembly, admission on the body's own tools where they cannot be stripped (Codex), and the body's compaction as the fallback where neither switch nor lever exists. The hand side keeps everything: gate, containers, worktrees, traces, capture sweep, spawn ledger. *(Extended 2026-08-30 by `31a20ff6`, the CLI-main exhaustion floor: with no rewind-to-fit and the body's own compaction pushed above arx's limit, a ContextWindowExceeded reported during the reset ritual is met by arx killing and respawning from the last checkpoint's state object plus the archived transcript handle, logged as its own D09 event; with no checkpoint in the thread, the floor is the transcript handle alone.)*

Vocabulary in `CONTEXT.md`: Body, Judge, Gate, Reset, Transcript log amended. The D12 handoff (whether arx's MCP surface exists and whether main and a CC-bodied hand share it) is answered: it exists, mounted into the child by arx, and the role decides which verbs it carries — a hand's carries none of main's.

**Left open, named:** the judge as a third participant (owner leaning, deferred); Codex's `review/start` if the gauntlet critic's schema ever converges on its findings shape; OpenAI's usage-policy text on third-party hosts of a ChatGPT login (repo README invites it, policy site unchecked); whether `-c project_doc_max_bytes=0` fully suppresses AGENTS.md discovery.
