Kind: question
Path: n/a
Context: The subject is what the owner should do next on arx, an agent harness he is building — a Rust shell around the model loop, with memory and context policy owned by the harness rather than bolted on as a tool. Nothing is implemented. The repo at ~/Projects/arx holds design prose only, all untracked, produced over ten design sessions since 2026-08-13: CONTEXT.md (the vocabulary), POSITION.md (a 421-line context ledger, newest banners at the top, earlier sections superseded in place), SURVEY.md (an outside-world sourcing map), docs/wayfinder/maps/arx-design/ (nine dive tickets D01-D09, seven research findings T01-T07, map.md), and — new this session — docs/research/memory-2026.md, a sourced sweep of the 2026 evidence on agent memory systems versus filesystem alternatives. The incumbent tool the owner uses daily is Claude Code, extended by a large personal skillbook of skills, hooks and agent definitions. His memory store is Tabularium, his own project at ~/Projects/Tabularium: a vector store over Qdrant with an embedding dedup gate, fact/decision/digest kinds, scopes, supersession and shelving, hot/ember grounding tiers pushed into context by a session-start hook. Rulings live in that store, cited by hex ids you cannot dereference — treat an id as a citation you cannot open, and judge the prose. Read the files before claiming.
Two prior debates over this corpus are settled ground, and their ledgers are readable at ~/.claude/discuss/2026-08-26-arx-plans/ledger.md and ~/.claude/discuss/2026-08-26-arx-premises/ledger.md. Do not re-raise their rows as new items; you may cite them. Between them they carried 33 live rows: a stale-document cluster, a seven-row observer cluster, a five-row thread cluster, five concrete holes, and twelve rows on charter and pricing including three blockers — no falsifiable claim of what arx does that the incumbent structurally cannot; a destination that excludes all executable work; and the thread admitted without a cost tally.
Since those ledgers were written, the owner ruled in conversation, and none of it is written down in the repo yet. The observer is dropped outright. The thread survives but is redefined as the WIP: not done means reset on a token counter, done means the record lands in a plain file rather than in the store. The digest operation is dead, replaced by a single state object that the main writes itself, carrying position plus the target and whether the target drifted — which folds the charter into it. Seats and multi-agent benches are gone; the participant set is main plus dispatched hands. He stated the reason for the collapse plainly: he cannot pay per token, so the bodies have to be subscription CLIs, and two CLIs mounting the same skillbook hooks is roughly what he already has today. He also stated that main could be API-backed but not the top model tier, that models no longer differ much, and that quality now mostly comes from the harness — which, if true, is the claim arx must be built to test.
The memory research landed the same session and cuts at Tabularium rather than at arx. Its findings, summarized: single-vector retrieval fails at small corpus sizes rather than merely being unnecessary there; dense retrieval finished last at all 28 tiers of a scaling sweep, with a grep-style file agent leading at the smallest tier; the vendor that invented write-time add/update/delete arbitration removed it and reported a 20-point gain; an operator audit of 10,134 stored entries kept 224, with cosine dedup flagging 2,943 near-duplicates of which manual review kept 7; an agent running on consolidated memory failed 54% of problems it had previously solved unaided; in the one benchmark run by a group with no product in the race, plain BM25 led on accuracy and cost 26x less energy than the nearest purpose-built system; and every shipped memory layer of 2026 converged on files. Against that, memory systems measurably beat full-context only above roughly a million tokens. One finding lands on arx itself: handed retrieval results inline, agents beat vector search with grep on every pair tested, but handed the same results as a file to open, the ordering inverted on half the pairs and the strongest configuration lost close to forty points — and externalize-plus-handle, arx's central admission mechanism, is file delivery.
The question is what to do next, and every answer on the table is contestable. Should the next step be to sweep the corpus straight — the stale rows, the dropped observer, the redefined thread — so the design says what the owner now believes? Should it be to write the falsifiable claim first, since two debates found none and a harness with no claim has no way to know if it worked? Should it be to build the smallest thing that runs, on the grounds that ten prose sessions produced twenty superseding decisions in one session and nothing has ever been executed? Should it be to rip the vector store out of the loop and rebuild memory as files plus lexical search, given the research? Should arx be abandoned in favour of continuing to extend the incumbent, which is what the subscription constraint has already half-forced? Attack whichever of these the evidence lets you attack, name what the owner is about to waste, and say what the actual next step is — as a claim that could turn out false.
