# D13 — The store's shape after the 2026 research

New ticket. Two research artifacts landed 2026-08-27 — a sourced sweep of the external evidence on agent memory systems (`memory-2026.md`) and a month of measurement against the owner's own live Tabularium store (`tabularium-in-practice.md`) — and nothing in the map points at either yet. D01 ruled the engine (`dbbe749c`, `d1ff8175`, `30e83788`) before this evidence existed.

## Question

- **Does arx build Tabularium v2 at all, given this evidence?** `dbbe749c` ruled arx gets its own memory engine — Rust, on Qdrant, starting empty — on the argument that v1 was shaped for a host arx does not control. The external research measures dense vector retrieval losing at every one of 28 corpus-size tiers tested, with arx's own corpus (order of a thousand notes) sitting an order of magnitude below the smallest tier where vector search had already lost. `d1ff8175` and `30e83788` describe how the engine would be built if built; neither says whether it should be, against evidence that postdates both.
- **What does the engine actually cost?** Flagged independently in two debate runs: the second store engine is unpriced, carried by locality taste alone once the original speed argument failed under inspection, with nobody weighing it against a localhost adapter to the existing v1 store (`S-SOL-5`, plans, agreed, major; `S-SOL-5`, premises, agreed, major — the same finding, reached twice, on separate evidence).
- **Does ripping the store out overreach what the research supports?** The next-steps debate's caution, agreed by both seats: grounding pushed at session start and supersession-with-a-validity-window both survive the research as vindicated pieces, and only vector recall and similarity dedup are the contested ones (`S-RUNE-3`/`S-SOL-5`, next-steps, agreed, major). A wholesale removal of the vector store is a bigger move than "vector recall loses at this scale" supports on its own — if anything changes here, it is one superseding ruling over the Qdrant commitment specifically (`d1ff8175`, `30e83788`), not a blanket retreat from the store.
- **Is the research doc itself reliable enough to rule against?** The next-steps debate flagged three places where the summary in `memory-2026.md` leans anti-store on inspection: its headline +20-point figure for dropping write-time arbitration rides on LoCoMo, a benchmark the same document separately shows has a 6.4%-wrong answer key and a judge that accepts 62.81% of deliberately wrong answers; its 26.5× energy figure is specific to the worst-performing system in the comparison table (Letta) rather than to "the nearest" purpose-built one (the nearest on accuracy, GraphRAG, is 3.6× — a number the document states plainly a few lines later); and the best-measured counter-case, a vendor A/B showing a real +12.5% accuracy gain concentrated in large codebases, is present in the sourced document but easy to drop in a retelling that only carries the headline (`S-RUNE-4`, next-steps, agreed, major). Separately, a defect was flagged in the document's own text near line 46, not only in how a retelling stated it (`S-SOL-9`, next-steps, agreed, major) — worth a direct re-check against the current file rather than assumed fixed or still present, since the flag and the file's edit history are close enough in time that either is possible.
- **Does the one arx-specific research result actually price arx's mechanism?** `memory-2026.md` §6 found that retrieval results handed to an agent inline favor grep over vector search on every pair tested, but the same results handed over as a file the agent must open inverted the ordering on half the pairs tested. Externalize-plus-handle is file-based delivery, which makes this the closest measured result to arx's admission policy — but the paper tested retrieval traffic specifically, which is the one category arx's own `40ebd8d3` exempts from admission and keeps inline. Both debate runs read this the same way: a warning with a gap in it, not a verdict, because the actually-unmeasured case is over-threshold arbitrary tool output behind a preview plus a handle, not retrieval results (plans debate, matching a fact already recorded in this scope; `S-RUNE-5` revised, next-steps, agreed, major). Whether that gap is enough to keep the mechanism as designed, or grounds for treating it as unvalidated until measured, is this ticket's to weigh.
- **What would the first real test look like, if one is run?** Two shapes were raised without being adopted as a ruling by either debate: an A/B that isolates externalize-plus-handle specifically, run against over-threshold tool output rather than accepting the mechanism as policy by default (`S-SOL-7`, next-steps); and a three-way comparison of lexical files, vector retrieval, and load-all behind one seam, run before any storage shape is picked rather than after (`S-SOL-6`, next-steps). Naming both here is not choosing between them.

## Resolution

A `/debate` run over the owner's two positions on the recall shape — a vector-then-BM25 funnel, and the bounce kept as the landscape — produced a ledger (`findings/debate/2026-08-27-arx-d13-recall-gate/ledger.md`, seats `rune`/`sol`, 3 rounds, 14 agreed rows, 2 contested, 1 withdrawn; both seats call rethink). Six rulings followed. Bullet by bullet, against the question above:

- **Does arx build Tabularium v2 at all?** Yes, restated rather than retracted. `c775b5c2` (superseding `dbbe749c`) keeps the own-engine ruling and replaces its substrate and deployment clauses: v1 was shaped for a host the owner does not control, v2 for a host he owns; the shell stays Rust (`30e83788`); the store starts empty, re-grounded on the v1 audit's junk rate rather than migration pain (`3ed57643` — 89% of adjudicated collisions judged distinct and rising, 44% of the store never reviewed, thresholds never tuned).
- **What does the engine actually cost?** Priced by the same ruling rather than left as unweighed taste: the gap the debate flagged — a second engine against a localhost adapter to v1 — closes on ownership of the host, not a speed argument. A second cost the grill surfaced along the way is priced too: `6523f41f` finds v1's cleaner inert for a month (about 3.8% coverage, 7 of 13 shelves hand-reverted on the writes it did make), so v1 ships none — only a constraint on a future one: read the store, emit a reviewable change set, never mutate a record in place.
- **Does ripping the store out overreach the evidence?** No. `c775b5c2` supersedes `dbbe749c` on exactly the two clauses the research contradicts — Qdrant, and the snapshot-based three-machine deployment — and says so rather than retreating wholesale. `095a930e` (superseding `d1ff8175`) narrows the same way: the engine crate and the localhost Ollama embedder stand, only the Qdrant container falls, deferred to an index adapter behind one seam if a measured cost ever earns it.
- **Is the research doc reliable enough to rule against?** Folded into this ticket's text rather than argued to a ruling, per both seats' agreement: the §6 externalize-plus-handle warning in `memory-2026.md` stays a D09 instrumentation target, not a D13 finding — the measured case in that section (retrieval results delivered as files) is what `40ebd8d3` already exempts from admission. The line-46 defect the ticket asked to re-check (`S-SOL-9`) is confirmed fixed in the current file; the 3.6× GraphRAG / 26.5× Letta split is stated separately in the source, not merged the way a retelling might merge it.
- **Does the arx-specific research result price arx's mechanism?** Same fold as above — a warning with a gap in it, not a verdict, because the case the paper left unmeasured is over-threshold tool output behind a preview plus handle, not retrieval traffic.
- **What would the first real test look like?** Answered by dispatch, not by ruling. **T08** (`T08-recall-shape-measured.md`, dispatched 2026-08-28, `assignee: hand-ex`) runs the three-way comparison this bullet named against a read-only copy of v1's 8,552-record store — text-only, vector-only, and v1's RRF hybrid as configured, on three query sets each carrying an answer column. This is the one bullet neither debate seat would rule unmeasured, and the one this ticket stays open on.

Beyond the six question bullets, the same debate settled the store's save-and-recall mechanics. `da0b0d8b` (superseding `3f7d9b5c`) splits save judgment by job: an inline landscape — the N nearest in-force same-scope claims, with content, returned on save intent — surfaces contradiction while duplicate judgment waits in a per-thread quarantine; `df14a2bc` stands, its "fold at a seam" now read as the doneness drain that empties quarantine. `27e7cea9` (superseding `dc06e97b`, a same-session correction — owner: "the suggestions should come from diff -> main writes") makes that drain two pens: a hand of a different model family from the thread's main reads the quarantine and returns suggestions, main applies them, the hand holds no save verb. `7be68c4a` fixes a claim to four required fields (question, answer, why, handle), with derivability checked at the drain rather than at the schema. Vocabulary for all of it (Claim, Quarantine, Drain, Landscape) is in `CONTEXT.md`.

**Closed 2026-08-28 on T08's numbers.** The recall shape is lexical only — BM25 over the claim files, no vector leg, no fusion; the embedder survives for the landscape's cosine leg and nothing else (`896b62ad`). T08 (`findings/T08-findings.md`) measured the three shapes on a read-only copy of the v1 store: on self-retrieval text-only led at recall@1 0.97, vector 0.95, and v1's RRF hybrid as configured fell to 0.85, below both legs; on the pairs set built by vector's own cosine, vector reached only 0.266 recall@10; and the funnel's premise — that BM25 alone would wade through similar hits — did not occur, 29 of 30 real queries carrying zero same-subject pairs in the text-only top-10. Rejected: the funnel (S-SOL-1, and its premise measured false), parallel hybrid (measured loss), vector-only. Owner: "ok, you win on q1." Noted for D09, not ruled: arx's scope is ~8k tokens today, so grounding could push the whole scope for months before a retrieval verb is exercised.
