## Problem / Solution

The native hand is the last body on the host. Its loop runs in arx, which is where the rulings put it, but its one tool executes in arx's own thread against `config_dir`, its gate is a locally constructed `AllowAll` that L2-02's table never reaches, it has no `recall`, and it writes a flat `threads/<thread>.<hand>.jsonl` while the other bodies leave a trace directory. Nothing distinguishes what the model may touch from what arx may touch.

This card draws the line the rulings describe. The loop, the provider stream and the key stay in arx's process on the host. The tool calls the model makes cross L2-02's gate on the host first — allow executes, deny returns the reason to the model as the tool result, ask holds the hand at the wall and sends a stop into main's window, whose steer is the answer — and then execute inside a container L2-07 built, kept alive for the brief and entered per call with `docker exec`. `read_file` reads from `/hand/repo`, so the store mask and the read-only mount bind it; a new `recall` tool, present only when the definition lists it, is served on the host by the engine and never touches the container. The hand's trace becomes the directory shape the other bodies have, with arx's own step rows swept in as `transcript.jsonl`. The provider key never enters the container's environment, argv or mounts.

## Decisions locked

- `BodyKind::Native` joins `in_container()`. `SpawnLedger::dispatch` routes it through `container_hand::prepare` (image check, toplevel, hand root, worktree when write-enabled; no credential step) and a new `container_hand::spawn_native_in_container(spec, hand_id, brief, delivery_tx, control_rx, prepared)` that starts the container and then runs L2-10a's loop on the host against it. `SpawnLedger::kill` treats it as the other container kinds (signal only; the thread's `Killed` carries the trace). The steer refusal while `Running` stays; steer while `Stopped` is delivered (the fake's path).
- The container is long-lived for the brief: argv `["sh", "-c", "while :; do sleep 3600; done"]` on the definition's `image` (default `DEFAULT_HAND_IMAGE`, `alpine:3.20`; a native definition needs no `image` key). `Container` gains `pub fn exec(&self, argv: &[String]) -> io::Result<std::process::Output>` running `docker exec -w <workdir> <name> <argv…>` with stdio captured, and `pub fn workdir(&self) -> &str`. Teardown as today: `kill`, `wait`, `remove`, diff, sweep, worktree and root removed.
- Tool execution is a seam, `trait ToolHost { fn read_file(&self, path: &str) -> Result<String, String>; }` in `native_hand.rs`. `ContainerHost { container }` implements it with one exec: `sh -c 'p=$(realpath -- "$1") || exit 3; case "$p" in /hand/repo/*) cat -- "$p";; *) echo "read_file error: path escapes the working directory" >&2; exit 3;; esac' _ <path>`; exit 0 → the stdout as the result (lossy UTF-8); exit 3 → `Err` with the stderr text; any other failure → `Err("read_file error: <stderr tail>")`. `LocalHost { cwd }` keeps today's `execute_read_file` for the unit tests only. `run_brief` takes `&dyn ToolHost` beside the provider.
- The gate: `HandSpec` gains `gate: GateConfig` (the resolved repo tier) and `user_gate: GateConfig` (the user tier as `cmd_run` loads it), both cloned at `resolve_hand_spec`; the hand thread builds `gate::Table` from them the way `cmd_run` does and every tool call crosses `Table::decide` before anything executes. `Allow` → execute; `Deny { reason }` → no execution, the tool result is `denied: <reason>`, the trace `gate` row carries `deny` and the reason; `Ask` → the hold. `gate::subject_field` gains `read_file` → `path` and `recall` → `query`, so `read_file(secret*)` and `recall(*)` rules match. Hooks are not run for hands (`GateConfig.hooks` ignored; noted in the card).
- The hold: on `Ask`, the loop sends `Delivery::Stop { hand, question: "tool <name> on <subject> — allow or deny? answer with the steer tool" }` (`Delivery::Stop` gains an additive `wall: Option<String>` carrying the tool name, `None` on the fake's path) and blocks on a channel the watcher feeds: the watcher thread now forwards `Control::Steer(text)` into an `mpsc::Sender<String>` the loop holds, and still sets the cancel flag on `Control::Kill`. The answer: a text that trims to `allow` (case-insensitive) executes the call; anything else is a denial whose reason is the text; the flag set while holding ends the brief with no delivery. Main, on draining a `Stop` with `wall: Some(tool)`, emits `Event::Wall { hand, tool }` before the stop injection (`KINDS` stays 17). The trace `gate` row for the call carries `ask` and then a second row `{"kind":"answer","text":…}`.
- `recall`: `ToolDef` named `recall` with one required string parameter `query`, on the hand's surface only when its definition's `tools` lists `recall`. Native definitions' `tools` is validated at `resolve_hand_spec`: every name must be `read_file` or `recall` (`dispatch: <agent> lists an unknown native tool <x>`); empty means `[read_file]`. Execution on the host: the first `recall` call opens `Engine::open(&spec.store_root, &format!("hand-{id}"))` (a read-only use; the quarantine directory it creates under `quarantine/hand-<id>/` is removed at teardown) and calls `Store::recall(&scope, &query, 10)` with `scope` = `HandSpec.store_scope` (new field, `Option<String>` from `resolved.store_scope`; `None` → the tool result is `recall error: no store scope configured`); the result is the claims array as JSON text. The gate sees it as tool `recall`, subject `query`. Nothing under the store root is ever mounted (L2-07's mask stands).
- The trace: `native_hand.rs`'s step rows (`request`, `assistant`, `termination`, `gate`, `answer`, `tool_result`, `error`) are written to `<root>/transcript.jsonl` during the brief and designated into the sweep as `transcript.jsonl`; the handle is `threads/<thread>.<hand>`; `trace.md`'s `body` is `native`. The flat `threads/<thread>.<hand>.jsonl` is no longer written for a native hand. `Delivery::Verdict` carries `trace: Some(handle)`, `bytes`, `usage` (the last step's) and `walls: vec![]`.
- The key: read from the env var in `spawn_native_in_container` exactly as today, held in the hand thread's `String`, used by the provider on the host; it appears in no `docker` argv, no `-e`, no mounted file. The container's environment is L2-07's (the image's own plus `HOME` plus the definition's `env` allowlist, empty for `hand-ds`).
- Grounding: unchanged in this card (the brief is the whole orientation, `69946e37`); the engine-served grounding push for native hands stays with L2-13's respawn work, where the hand's own window is rebuilt.
- Tests: the nine native e2e tests in `claude_main.rs` keep their names and assertions, with the trace path re-pointed from `threads/main.hN.jsonl` to `threads/main.hN/transcript.jsonl` and the verdict suffix to `(trace: threads/main.hN)`; `layer_close.rs`'s `l1_close_loop_on_host` needs no change unless it reads the native trace path (check and say); `tests/scripts/l1-close.json` is untouched. The native unit tests in `native_hand.rs` run against `LocalHost` and a scripted provider, no Docker.
- Codex gate: behaviour-changing diff, the gate runs. The provider limit is in force until 2026-09-07 08:38: one attempt, `gate_run: no` with the reason, and the reviewer gates on brief conformance.

## Chosen without a grill

- **`docker exec` into a long-lived container, not a tool-server process.** The loop is arx's and stays on the host; what must cross is one command per tool call. `docker exec` exists on this host, needs no script in the image, and works for any future tool (a `Bash` tool is one more exec). Rejected: the fake's line protocol as a tool-server (a second protocol to maintain inside every image); a container per tool call (a `docker run` per `read_file`, and no place for a write-enabled hand's worktree state between calls).
- **`realpath` inside the container for the escape check.** The check must hold where the read happens; busybox has `realpath`. Rejected: canonicalising on the host against the mount source (a second view of the same tree, and wrong once a hand can write).
- **Ask holds on the existing stop and steer.** `5e8da52e` says the request crosses as a stub-shaped event and the parent's answer is the correction; `Delivery::Stop` and the ledger's steer-while-stopped path are exactly that, already proven by the fake. Rejected: a new `release` verb; main's terminal `a/A/d/D` loop (that loop is main's own gate, blocking main's stdin).
- **Deny returns to the model as the tool result.** `ebe94e38` calls the deny-only gate for hands the same as main's; a denied call the model can read about lets it route around, and the trace row records it. Rejected: ending the brief on a denial.
- **A `ToolHost` trait with one production adapter and one test adapter.** Unit tests of the loop must not need Docker; the interface is the test surface. Rejected: a Docker-only loop with every loop test moved to e2e.
- **`recall` through a per-hand engine handle on the host.** Main's engine lives in `cmd_run`'s thread and is not shareable; the engine is files on disk and its recall is lexical, so a second handle is cheap. Rejected: routing recall through main's window as a delivery (a hold on main's loop for every recall); mounting the store (`e79bed85`).
- **The native trace becomes a directory with `transcript.jsonl` inside.** One trace shape for every body in a container; the step rows survive as the file `e2e92711` names. Rejected: keeping the flat file beside the directory.
- **Hooks skipped for hands.** `GateConfig.hooks` are main's PreToolUse hooks; a hand has no Claude Code process to run them in. Rejected: running them on the host for hand calls.
