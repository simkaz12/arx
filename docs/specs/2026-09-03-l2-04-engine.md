## Problem / Solution

L1-06 fixed the memory seam with the thinnest adapter that closes the loop: one JSONL file per scope, substring recall, a drain that appends. It has no lineage, no validity, no real ranking, no git, and nothing that can tell a paraphrased contradiction from a new fact. The design ruled the real store as Tabularium v2 in Rust over a file store that is a git repository, lexical recall, an embedder kept alive for exactly one job, and a four-field claim.

This card ships that engine as a second adapter behind the same trait: `Engine` in `crates/arx-engine`, per-claim markdown files under a directory per scope, the store root as its own git repository committed through the `git` binary, BM25 recall, supersession and validity, the ember as a record kind, and the landscape as a cosine leg over an Ollama embedder unioned with the lexical leg. Nothing outside the engine crate moves. Main keeps opening `FileStore` until L2-05 swaps it; the live `store/` at the repo root is never read or written by anything this card adds.

Two findings against layer 1 were taken before the brief. L1-06's trait cannot express the flags or lineage the card's done-when names, so the trait is widened by default-bodied methods with the six shipped signatures byte-identical, and the finding is recorded in the map's frontier note. T08's fixture and scripts are gone from /tmp and the owner ruled no export from Tabularium, so the done-when's T08 clause became a ranking-sanity fixture; the card text is amended to match.

## Decisions locked

- The trait is widened, never moved. Three default-bodied methods are added to `Store`: `save_with` returning a `Landscape`, `recall_with` and `decisions_query_with` taking `&RecallOpts`. Their default bodies delegate to `save`, `recall`, `decisions_query`, so `FileStore` compiles untouched and every L1 test stays as it is. The six existing signatures do not change by a character. `serve` is untouched; widening the wire with the optional flags is L2-05's, which owns the verbs over the engine.
- Record model, additive on `Claim` with serde defaults so L1-06's JSONL rows still parse: `lifecycle` (`in_force` | `superseded`), `validity` (`valid` | `invalid`), `supersedes`, `superseded_by`, `invalid_reason`, `created_at` (unix seconds). `ClaimKind` gains `Ember`. `SaveIntent` gains optional `supersedes`. Lifecycle and validity are independent axes. Dropped from v1 by the owner's cut: archived, shelved, revoked, bury, decay, feedback score, recall counts, recurrence ladders, promoted_from, provisional, audience roles, purpose facets. The chain is walked over `supersedes` pointers, never stored as snapshots. Nothing is destructive.
- A claim file is one markdown file with YAML frontmatter at `<root>/<scope>/<id>.md`; an ember at `<root>/<scope>/embers/<id>.md`. Files are truth; every index is an adapter rebuilt from them. The owner re-types the hot tier by editing `label: hot` in a file; there is no verb for it. Quarantine keeps L1-06's exact path and JSON shape, `quarantine/<thread>/<seq>-<id>.json`, because `read_quarantine_listing` in `main.rs` and the L1-close tests read it.
- The store root is its own git repository. `Engine::open` runs `git init` when `<root>/.git` is absent and writes `<root>/.gitignore` holding `quarantine/` and `.index/`. Every promotion, ember and invalidation is one commit through the `git` binary with `-c user.name=arx -c user.email=arx@localhost`; no libgit2. Sync is the owner's `git pull` and `git push`; the engine never touches a remote. A git failure is a `StoreError::Git` and leaves candidate files in place.
- Scopes are directories. A save, recall, query, decision, grounding or ember into a scope with no directory under the root is refused with `StoreError::NoScope`; the owner registers a scope with `mkdir`. Names validate as before, and `quarantine`, `.index`, `.git`, `embers` are reserved.
- The ember rides in the claim struct as `ClaimKind::Ember` with the owner's text in `answer`, `label: ember`, empty `question` and `why`. The four-field check binds fact and decision only. Grounding always returns embers; recall and decisions_query never do. `Engine::ember(scope, text, handle)` writes and commits; the `arx ember` command that mints the handle from the live thread is L2-05.
- Recall is lexical only (`896b62ad`): hand-rolled BM25, k1 = 1.2, b = 0.75, tokenizer lowercases and splits on non-alphanumeric characters, drops tokens shorter than two characters, no stemming, no stop list. The document is `question + " " + answer + " " + why`. Zero-score claims are excluded. Ties break by `created_at` ascending, then id. The lexical index is rebuilt in memory on open and after each of the engine's own writes; hand edits between sessions are picked up at the next open.
- Default filters: recall and decisions_query return `in_force` and `valid` claims; `include_superseded` admits `superseded`, `include_invalid` admits `invalid`. `decision(scope, id)` returns a decision-kind claim by id whatever its lifecycle or validity. Grounding returns hot claims that are in force and valid, then every ember, each group by `created_at` then id.
- The embedder has one job. An `Embedder` trait in the engine crate with two adapters: `OllamaEmbedder` over `POST <url>/api/embed`, and `HashEmbedder`, a deterministic 64-dimension hashed bag of words for tests. Recall, decisions_query and grounding never embed; a test counts calls and asserts zero. Vectors live under `<root>/.index/<scope>.vec.jsonl`, gitignored, tagged with the model name; a row with another model is ignored and re-embedded. Embedding is eager after a drain commit and lazy as backfill at the next landscape, in one batch call. The nomic task prefix is not used.
- The landscape is BM25 top-5 unioned with cosine top-5 over in-force, valid, same-scope claims of both kinds, deduped, cosine hits first by cosine descending then lexical-only hits by score descending, capped at ten. Not a gate: nothing is refused, nothing bounces. `Landscape { claims, legs, degraded }`: `legs` is `["cosine","bm25"]` or `["bm25"]`; `degraded` is `Some(reason)` only when an embedder is configured and the call failed, `None` otherwise. The candidate itself is embedded from `question + " " + answer` and never persisted before promotion. The trait's `save` returns `save_with(..).claims`.
- Ids are UUIDv4, hyphenated, so the owner's 8-hex citation habit carries over. `created_at` is minted by the engine at save.
- The drain is all-or-nothing per call: validate every candidate first (scope directory exists, four fields non-empty, a named `supersedes` target exists in that scope and is in force), then write every claim file and rewrite every superseded predecessor with `lifecycle: superseded` and `superseded_by`, then one commit, then delete the candidate files. A candidate whose claim file already exists is skipped and its file deleted, so a drain after a failed delete is idempotent. `DrainReport { promoted }` counts files newly written. The two-pen judged drain is L3-03; this drain applies no suggestions.
- Harness untouched: `crates/arx`, `sidecar/`, `arx.toml`, the root `.gitignore`, the live `store/`. Every test runs in a temporary directory. The Ollama endpoint is the caller's to supply to `Engine::with_embedder`; the config key is L2-05's. The owner pulled `nomic-embed-text` to the host today; the live check uses `http://localhost:11434`.
- Prose rule: everything written passes `~/.claude/skills/unslop/SKILL.md`; read it by path before writing any doc comment or the card paragraph. No inline comments beyond doc comments on public items.
- No commits in the arx repository, no git writes there. Prior state is inspected read-only: `git status` / `diff` / `log`, and `git show <ref>:<path>` to read a file at a ref. The engine's own `git` calls run only against temporary store roots created by tests.
