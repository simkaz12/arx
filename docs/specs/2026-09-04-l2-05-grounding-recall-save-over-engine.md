## Problem / Solution

Main still runs over L1-06's `FileStore`: flat `store/<scope>.jsonl` files, a landscape that is substring ranking, a drain that appends rows one by one with no history. L2-04 landed the engine behind the same trait, one markdown claim per file in a git repository, BM25 recall, a real landscape at save intent, a one-commit drain, embers as a record kind, and proved `serve` drives it unchanged. Nothing in `crates/arx` uses it yet.

This card swaps main onto the engine. Grounding at spawn becomes the scope's hot claims and embers from the engine. Recall, decisions_query and decision cross `serve` into it. A save from main is intent, landscape back, candidate into the per-thread quarantine, no commit; the drain's promotion is the commit. The drain grows its two-pen shape on main's surface: it takes one suggestion per candidate (promote, promote-superseding, drop) and main applies them as one commit carrying the thread handle; the proposing hand of `27e7cea9` is stubbed as "promote everything" until L3-03. `arx ember` mints the owner's guidance into the store with the live thread's handle, as `490cf78d` assigned to this card. L1-06's done-check keeps its assertions over the engine.

## Chosen without a grill

- **`&mut dyn Store` over a concrete `Engine` at the call sites.** `serve` is already `&mut dyn Store`, the gate precedent exists, and the trait's error type survives, so `e66e210c`'s reason for the typed calls is met without naming the adapter. Rejected: `&mut Engine` everywhere (pins main to one adapter, and `null_store_compiles_against_the_trait_at_the_same_call_site` exists precisely to keep that door open).
- **`degraded` to the terminal, not the tool result.** Widening the save result would change `serve`'s output and the L2-04 test `engine_drives_the_l1_call_site_unchanged`; the operator is who acts on a dead embedder. Rejected: a `Landscape` object as the tool result.
- **Embedder wired from `[store] embedder`, model fixed to `nomic-embed-text`.** `c747476b` shipped the embedder in L2-04 for the landscape; leaving main without it would make the cosine leg dead code in the loop. The model name is not configurable yet: one owner, one host Ollama, one pulled model. Rejected: no embedder in main (the leg never runs); a model key (ceremony for one value).
- **Three drain actions, `merge-into` reduced.** `27e7cea9` names promote, merge-into, supersede X, drop. Merge-into is authoring: the merged text is a new candidate that supersedes the target, so it is a save with `supersedes` followed by `drop` of the original, both already expressible. Rejected: a `merge_into` action that edits a stored claim (the engine's claims are immutable files with lineage; editing one in place is what `29e7e794` refuses).
- **`None` means promote everything, `Some` must cover every candidate.** The stub proposer needs a shape that L3-03 replaces without touching the verb, and an empty list must not silently mean "promote all". Rejected: `drain` with no suggestion input (L3-03 would have to change the seam); partial lists leaving the rest in quarantine (a drain is "once, at doneness" per `da0b0d8b`).
- **The drain commit subject carries `<thread>@<turn>`.** The card's "one commit carrying the thread handle" needs the turn as well as the thread; each promoted claim file already carries its own save handle. Rejected: changing `drain()`'s existing subject (L2-04's tests and FileStore's path).
- **`arx ember` refuses without a committed turn.** `490cf78d` says the command mints the handle from the live thread; a handle with no turn behind it is a fake handle. Rejected: turn 0 as a sentinel.
- **Scope registration stays `mkdir`, with no `check-config` line.** `f09b9ed4` puts registration with the owner. A `store:` line in `check-config` would change output the last two cards locked byte-identical and the 8 `check_config` tests. Rejected: auto-creating the scope in `cmd_run` (the exact create-on-first-write `f09b9ed4` retired).
- **Live `store/` left alone.** The engine wants a nested git repository at the store root; the repository's `store/` is tracked in the outer repo and holds FileStore rows. Which way to resolve that (migrate and untrack, or a root outside the repo) is the owner's; the card runs in scratch workspaces meanwhile.
- **L2-05 before L2-07 and L2-03.** L2-03 is a prototype the owner reacts to in person. L2-07 needs the owner in the `docker` group: the daemon is up, the socket is `root:docker`, the owner's user is in neither.
