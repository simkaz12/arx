# L2-14 — arx's own tools gated in the handler

## Problem / Solution

Every arx-served call on a Claude Code main crosses the sidecar pipe twice: the SDK asks `canUseTool`, the sidecar sends a `gate` event, Rust decides and answers, the SDK then runs the MCP handler, the sidecar sends the `store`, `hand` or `file` event, Rust executes and answers. The gate row's place before the tool's effect is a side effect of that sequencing, enforced by nobody.

This card makes it one crossing. The sidecar lists its own registrations, by their full `mcp__arx__<name>` form, in `allowedTools`, which the SDK documents as auto-approving a bare entry before the callback is consulted. The three Rust handlers gate first: the same `decide`, the same `Event::Gate` row, the same `ask` on the terminal with its two rows and its rule append, and on a deny the reason returned to the model as the tool result with nothing executed and no effect row written. The ordering that was accidental becomes explicit code. `canUseTool` stays for tools the body owns, exercised by the stub's bare `tool:` trigger.

## Decisions locked

- **`allowedTools`.** In `sidecar/claude-main.mjs`, the `query` options gain `allowedTools: arxTools.map((t) => 'mcp__arx__' + t.name)`, derived from the same array passed to `createSdkMcpServer`, so the list and the registrations cannot drift. No `permissionMode` is set. `canUseTool` stays in the options, unchanged.
- **The SDK's warning.** Listing bare entries makes the SDK emit `process.emitWarning` with code `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED`. The sidecar installs `process.on('warning', …)` that drops that code and writes any other warning to stderr as `<name>: <message>`, and arx starts the sidecar with `node --no-warnings` so Node's default printer is silent. Nothing about that warning ever reaches the operator's terminal.
- **The gate in the handler.** In `main.rs`, the `on_gate` closure's body becomes a function usable from four places: `fn gate_call(…, call: &GateCall) -> GateVerdict` carrying exactly today's behaviour (decide; `Event::Gate` row with `by`/`reason`; on `Ask`, `TerminalMsg::Ask`, the `a`/`A`/`d`/`D` loop with the rule append on `A`/`D`, the second `Event::Gate` row with `by: "operator"`, the closed-stdin deny row). `on_gate` calls it for body tools. `on_store`, `on_hand` and `on_file` call it first, with `GateCall { tool: "mcp__arx__" + verb-or-tool, input: args.clone() }`, where the verb is the store or hand verb and the tool is `read_file`/`edit_file`.
- **On deny in a handler.** Nothing executes and nothing else is written: no `Event::Spawn`/`Tap`/`Steer`/`Kill`, no `file` row, no store effect. The tool result is `{"error": "gate denied <tool>: <reason>"}` with `<tool>` the prefixed name and `<reason>` the decision's reason, or the verdict label `deny` when the decision carries none. The sidecar renders it as it renders any result of that tool (JSON text for store and hand, the `error` string for file).
- **Ordering, now explicit.** The gate row is the handler's first write; the effect row (spawn, tap, steer, kill, file) follows; the reply turn row follows the effect rows. The auto-steer after a stop keeps its gate row as the row immediately after the stop injection.
- **The stub sidecar** stops emitting gate events for arx's own tools: the `crossGate('mcp__arx__' + …)` calls leave the `store:`, `hand:`, `file:` and auto-steer triggers, which emit their event directly; the `file:` trigger's try/catch goes with it. The bare `tool:` trigger keeps emitting `gate` events, since that is the body-tool path `canUseTool` still owns.
- **What stays byte-identical.** `Event::Gate` and its rows; every reason string the `Table` produces; `GateCall`, `GateVerdict`, the `Gate` trait; `subject_field`; `run_turn`'s signature and its four arms; `SpawnOpts`; the `init` op; the L1-close script; every existing test's assertions.
- **`arx_ping`.** If the real sidecar's `arx_ping` reaches Rust as a store verb, it is gated like the rest; if it answers inside the sidecar, it crosses no gate and that is accepted: it is a probe. Say which in the verdict.
- **Codex gate:** behaviour-changing, so the gate runs at end of work; the provider limit holds until 2026-09-07 08:38, so one attempt, `gate_run: no` with the reason, and the reviewer gates on brief conformance.

## Chosen without a grill

- **The list is derived, not written.** Twelve names typed by hand would drift from the registrations; a map over the same array cannot. Rejected: a literal array; `mcp__arx__*` (the SDK's runtime matcher for that form was not found in the bundle, and a wildcard is a second grammar for the same fact).
- **`--no-warnings` plus a listener**, rather than a listener alone, because Node prints a warning by default even when a listener exists. Rejected: `NODE_NO_WARNINGS` in the environment (the sidecar's environment is the owner's); swallowing every warning.
- **The deny result is an error object**, the same shape L2-03a gave a failed file call, so the model reads one shape for "arx refused". Rejected: an empty result; a result mimicking the SDK's permission-denied text.
- **One function, four callers.** The alternative, a second copy of the ask loop in the handlers, is the locality loss the owner accepted knowingly; one function keeps it to one place. Rejected: duplicating the closure body.
