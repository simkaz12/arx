## Problem / Solution

A native hand today makes exactly one model call. `run_one_turn` streams one response, executes the tool calls a `ToolUse` termination carries, and stops — the tool results never reach the model. Its window is a bare `Vec<Message>` pushed in three places. Its kill is not live: the per-item `control_rx.try_recv()` runs only when `SseChunks::next` yields an item, and a vendor stall made of `: keep-alive` comment lines yields nothing, so the thread holds the socket until the 60 s whole-request timeout; the shipped kill test passes only because the process exits and reaps the thread.

This card is the loop. A brief runs as steps: call `complete`, append the assistant message, and if the termination is `ToolUse` execute the calls, append their results, and call again; `EndTurn`, `MaxTokens` and `Refusal` end it, as does a step cap from the definition. The window becomes a type with `append` and `rewind` and no way to splice, and the loop only appends. The kill becomes live through a cancel flag the adapter polls between reads: a watcher thread turns `Control::Kill` into the flag, `SseChunks` checks it after every line, and the loop checks it after every item, so a keep-alive stall ends within one line of the kill. `build_provider` takes the flag; the `Provider` trait and its types are byte-identical. The gate a native hand's tool calls cross stays the local `AllowAll` L1-10 left; wiring the real gate is L2-11's.

## Decisions locked

- The loop lives in `native_hand.rs` as `run_brief` replacing `run_one_turn`'s single call: build the window from the brief; loop `step = 1..=cap`: `provider.complete(system, window.as_slice(), tools)`, consume the stream into one assistant `Message` (text blocks and tool calls in order) plus the terminal's termination and usage, `window.append` it; on `ToolUse` execute every call in order through the existing gate-and-dispatch code, `window.append` one `Role::Tool` message per result, continue; on any other termination break. The verdict text is what `run_one_turn` builds today from the last step's assistant text (the mechanical fallbacks kept), `usage` is the last step's usage.
- The step cap is the definition's `steps: Option<u32>` frontmatter key (additive on `RoleConfig`, `RoleRow`, `HandSpec.steps: u32`; default `DEFAULT_STEPS = 16`; `0` refused at config resolution with `<agent>.steps must be positive`). Reaching the cap with a `ToolUse` still pending ends the brief with the verdict `native hand stopped at the step cap (<n> steps)` and the usage of the last step. No tool calls are executed on the step that hits the cap.
- The window is `pub struct Window { messages: Vec<Message> }` in `provider.rs` beside `Message`: `new(brief: &str) -> Window` (one `Role::User` text message), `append(&mut self, m: Message)`, `rewind(&mut self, keep: usize) -> Vec<Message>` (truncates to `keep` messages, returns the cut tail in order; `keep >= len` returns empty), `as_slice(&self) -> &[Message]`, `len`. No `insert`, `remove`, `retain`, `drain` or `DerefMut` to the vector. `rewind` is used by no caller in this card.
- The cancel flag: `pub type Cancel = Arc<AtomicBool>`. `build_provider(kind, base_url, api_key, model, cancel: Cancel) -> Box<dyn Provider>`; `OpenAiCompatible` stores it and `SseChunks` holds a clone. After every `read_line` in `SseChunks::next`, and before the first, the flag is checked: set → the iterator returns `Some(Err(ProviderError::Fatal("killed".into())))` once, then `None`. `AnthropicStub` takes the flag and ignores it. The `Provider` trait, `Chunk`, `Termination`, `ProviderError`, `Message`, `ContentBlock`, `ToolDef` do not change.
- The watcher: `spawn_native_hand` creates the flag, spawns one thread that loops `control_rx.recv()` — `Control::Kill` sets the flag and the thread ends; `Control::Steer` is dropped (the ledger refuses steer for a native hand mid-turn and the existing test `native_entry_steer_is_refused_mid_turn` stays); channel closed → the thread ends. The loop checks the flag after every stream item and after every tool execution; set → no delivery is sent (the ledger already wrote the killed row and pushed `Delivery::Killed`, as for every host body).
- `read_timeout` on the client is not added; the whole-request 60 s timeout stays the bound on a byte-silent stall. The card's "bounded time" is the flag on a keep-alive stall.
- The fake server gains `FakeScript::Sequence(Vec<FakeScript>)`: the listener answers the n-th connection with the n-th script and refuses any further connection with a 500 and a recorded count, so a multi-step e2e can pin request order and count.
- `native_hand_tool_call_executes_once_and_makes_no_second_request` keeps its name and is re-pointed: the tool is executed once, a second request is made carrying the tool result, no third request is made. Every other L1-10 test keeps its assertions; the runner lists any line it edits.
- Codex gate: behaviour-changing diff, the gate runs. The provider limit is in force until 2026-09-07 08:38: one attempt, `gate_run: no` with the reason, and the reviewer gates on brief conformance.

## Chosen without a grill

- **A cancel flag between reads, not a read timeout or an async runtime.** The carried stall is keep-alive lines, which do return from `read_line`; a flag polled there ends it within one line and needs no new dependency, no runtime and no trait change. A read timeout cannot resume a streaming response (the connection is gone once it fires) and `tokio` is absent from the workspace. Rejected: `blocking::ClientBuilder::read_timeout` with a resume loop; an async client on a private runtime behind the sync trait.
- **The flag enters through `build_provider`, not the trait.** The trait is ruled stateless and L1-10's signature is locked; the factory is arx's own composition point. Rejected: a `cancel` parameter on `complete`.
- **A watcher thread per hand.** The loop is blocked inside the stream when a kill arrives; something has to receive it. One thread that only sets a flag is the smallest receiver. Rejected: polling `control_rx` from inside the adapter (the adapter would learn the ledger's types).
- **`steps` as a definition key with a default of 16.** A cap is structural per definition, like `write` and `tools`; sixteen steps is Goose's order of magnitude for a bounded brief and is only a stop against spinning. Rejected: no cap (a tool loop that never ends); a `[main]` global.
- **Usage is the last step's.** Occupancy is what the last prompt cost, which is the number the gauge (L2-10b) wants; summing steps would measure spend, not the window. Rejected: summed usage.
- **`rewind` lands unused.** The op-set is the card's deliverable and L2-13 is its first caller; landing the type now keeps the loop from growing a splice by accident. Rejected: leaving `rewind` to L2-13.
- **The gate stays `AllowAll` here.** The trace found native tool calls never reach L2-02's gate; that is L2-11's card by name ("gate on the host"). Rejected: rewiring it in passing.
