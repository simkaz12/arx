## Problem / Solution

The sweep the card describes already runs: since L2-07 every hand and the judge live in a container, and on the return path `container::sweep` writes `threads/<thread>.<hand>/trace.md`, the worktree diff, the `out/` mirror and the body's own session file before the verdict is sent. L1-08's raw dump is an `unreachable!()` arm. What the sweep still owes the rulings is a sha per swept path and a capture timestamp, both deferred by L2-07 to avoid pulling a hashing crate, and a check that proves it never touches the store.

The drain is the work. The engine takes a suggestion list and applies it all-or-nothing in one commit, but the only caller is main's own `drain` tool, whose production schema is empty, so main can only promote everything: main draining alone, the single pen the rulings forbid. No hand can see the quarantine, nothing records a drain in the transcript log.

After this card, `drain` is two calls. The first dispatches the drain hand, a role read from `agents/drain.md`, with the quarantine and each candidate's landscape written into its `/hand/out`, the thread's `threads/` mounted read-only, and the repository mounted read-only like any read-only hand. Its reply is JSON under an arx schema, validated at delivery like the judge's, and rendered onto main's next turn one candidate per line. The second call names that proposal by hand id, carries main's overrides where it read a candidate differently, and applies through the engine's existing path: one commit, one `drain` event. With no drain agent configured the first call refuses; with no proposal the second refuses. The trace frontmatter gains `sha256` per path and `captured_at`.

## Decisions locked

- The sweep half is shas, timestamp and the store-untouched proof. The trace directory layout, the `Delivered` event and the verdict line do not change. The frontier entry records that the sweep itself landed in the container cards.
- `drain` with no `proposal` is the trigger: it dispatches the drain hand and returns its id. `drain` with `proposal: "<hand>"` applies. `overrides` is a per-candidate list on the apply call. `note` is free text on the trigger, appended to the hand's brief.
- The trigger refuses when `agents/drain.md` is absent or the quarantine is empty. Apply refuses without a proposal, with a proposal this session never received or that was malformed, or with an override naming an id outside the proposal. No promote-everything path survives on the tool surface; `Engine::drain()` stays as a library method with its tests.
- Suggestion verbs are the engine's: `promote`, `promote` with `supersedes`, `drop`. Merge-into is a new candidate saved superseding the target followed by a drop of the original; no engine change.
- The hand sees the quarantine by push: `drain-input.json` with every row and, per row, the landscape the engine computes for that candidate's text at trigger time. The thread's `threads/` directory is mounted read-only so `handle.turn` resolves against `threads/<thread>.jsonl` and hand traces. The repository is mounted read-only. No store tool inside the hand.
- The proposal is rendered for main, not pasted: `[hand h6 drain proposal] N candidates (trace: threads/<thread>.h6)` then one line per candidate `- <id> promote — <reason>`, `- <id> promote superseding <X> — <reason>`, `- <id> drop — <reason>`. The raw JSON stays in the hand's trace. A malformed reply arrives as `[hand h6 drain proposal malformed] <reason> (trace: …)` with a `schema` event carrying the reason, and no proposal is stored.
- Main decides per candidate. Asking the operator when unsure is main's own conversation; an operator who wants every apply confirmed puts an `ask` rule on `drain` through the gate. No new mechanism.
- Family: the drain row's family is compared with main's through `judge::family`; a match writes a `family` event and a terminal notice, never refuses.
- The drain role is dispatched only through the `drain` tool. `dispatch` with agent `drain` is refused. `agents/drain.md` is not listed in the roster main sees.
- One new event kind, `drain { hand, promoted, dropped, overrides }`, written after the commit. The proposal's arrival rides the existing `delivered` and `schema` kinds. `KINDS` grows to twenty.

## Chosen without a grill

1. Input and schema reach the hand through `/hand/out`, where the judge's schema already goes; `threads/` is a read-only mount at `/hand/threads`. Alternative rejected: excerpting the minting turns into the input file, which loses the hand traces the handles sit beside.
2. The proposal lives in memory for the session; after a reset or reopen main triggers again. Alternative rejected: writing `proposal.json` into the hand's trace after the sweep, which would break the write-once index.
3. `captured_at` is unix seconds, matching the engine's `created_at`; the hash is SHA-256 through `sha2`.
4. The hand's brief is a constant in `drain.rs`, not a second file under `prompts/`.
5. The role is `agents/drain.md`, optional, outside the roster and refused through `dispatch`.
6. The `drain` event carries counts only; the proposal rides `delivered` plus `schema`.
7. The swept `drain-input.json` is the record of dropped candidates; no doneness file.
8. Coverage is validated against the snapshot at delivery and against the live quarantine by the engine at apply.
9. The codex stub learns the drain schema; the fixture's drain agent runs on it, so the fake body is untouched.
10. Refusal texts as written in Scopes 4 and 5, exact, since the tests grep them.
