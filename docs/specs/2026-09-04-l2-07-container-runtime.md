## Problem / Solution

Every hand runs on the host today. `claude -p` and `codex exec` are spawned with arx's whole environment, `HOME` included, in `config_dir` itself, one `ls` away from `store/` and `threads/`. The fake hand L1-07 proves the ledger with is not a process at all: a Rust closure on a thread inside arx. Nothing computes a worktree, nothing sweeps anything at teardown, and a kill discards the trace outright. The rulings above describe a runtime that does not exist in the code.

This card builds that runtime and moves the fake into it. A hand's body runs in a Docker container arx creates and destroys: the repository mounted at `/hand/repo` (a detached git worktree at `HEAD`, read-write, for a write-enabled hand; the live tree read-only for everyone else, with the store root masked by an empty read-only tmpfs so no claim file is ever visible), an empty home at `/hand/home`, an output directory at `/hand/out`, the arx user's uid and gid, and an environment that is exactly what the image ships plus `HOME` plus the names the agent definition's `env` allowlist copies from arx's environment. At teardown, on a clean exit, a crash or a kill alike, arx sweeps the designated paths into `threads/<thread>.<hand>/` — a `trace.md` index, `worktree.diff` against the spawn base, the output directory — then removes the worktree and the container. The verdict carries the trace handle; a killed hand's stub carries it too. The fake becomes a POSIX shell script embedded in the binary, speaking the same `[delay:]`/`[stop:]`/`[verdict:]` grammar over stdin and stdout, plus the probes this card's done-when needs. The claude-code, codex and native bodies stay on the host in this card, untouched; they move in with L2-08, L2-09 and L2-11 over the seam this card lays.

## Decisions locked

- Docker is driven through the `docker` CLI via `std::process::Command`, the way `claude`, `codex` and `node` are driven today. No Docker API crate. No new dependency in `crates/arx/Cargo.toml`.
- One new module, `crates/arx/src/container.rs`, holds the runtime: the hand root on disk, the worktree, the container, the sweep. It imports only `std`, `serde`, `serde_json` — never `crate::` — so an integration test can `#[path]`-include it. It carries no inline `#[cfg(test)]` module (the include hazard).
- The container's shape, fixed for every body kind: `docker run -i --rm --name <name> --label arx.hand=<hand> --label arx.thread=<thread> --user <uid>:<gid> -e HOME=/hand/home [-e KEY=VALUE per allowlisted name] --mount type=bind,src=<repo mount>,dst=/hand/repo[,readonly] --mount type=bind,src=<root>/home,dst=/hand/home --mount type=bind,src=<root>/out,dst=/hand/out [--tmpfs /hand/repo/<store rel>:ro] --workdir /hand/repo/<config_dir rel> <image> <argv...>`. `uid`/`gid` are read from the metadata of the hand root arx just created (`std::os::unix::fs::MetadataExt`), so no libc crate. The container name is `arx-<hand>-<pid>-<nanos>`; the same suffix names the hand root, so parallel test workspaces never collide.
- The repo mount: `toplevel = git -C <config_dir> rev-parse --show-toplevel`. Not a repository → dispatch is refused at the ledger with `dispatch: <config_dir> is not inside a git repository` and a `refused` row, the way `refuse_dispatch_writes_a_refused_row_and_mints_no_hand` already refuses. Write-enabled: `git -C <toplevel> worktree add --detach <root>/worktree HEAD`, mounted read-write; no commit to base on → refused with `dispatch: <toplevel> has no commit to base a worktree on`. Not write-enabled: `<toplevel>` itself, mounted `readonly`. The container's workdir is `/hand/repo/<rel>` where `rel` is `config_dir` relative to `toplevel` (empty when they coincide).
- The store mask: `store_root = <config_dir>/store` (what `cmd_run` opens at `main.rs:958-962`). When `store_root` lies under `toplevel`, the container gets `--tmpfs /hand/repo/<store_root rel toplevel>:ro` on top of the repo mount, for both mount kinds — a tracked copy in a worktree is masked the same way as the live directory. Verified live on this host: `--tmpfs /m:ro` mounts and `touch` inside it fails with `Read-only file system`.
- The hand root on disk: `std::env::temp_dir()/arx-hands/<hand>-<pid>-<nanos>/` with `home/`, `out/` and, write-enabled only, `worktree/`. Created before the container, removed after the sweep (`git worktree remove --force` then `git worktree prune`, then `remove_dir_all`). The root path is written into the spawn row as `root` so tests and the owner can find a running hand's worktree. Nothing new appears inside the target repository; `.gitignore` is not edited.
- The environment allowlist is the agent definition's `env: [NAME, ...]` frontmatter key (default empty). Each name is copied from arx's own environment at spawn as `-e NAME=<value>`; a name absent from arx's environment is skipped silently. `HOME` is always set to `/hand/home` and is not an allowlist entry. Nothing else reaches the container.
- Agent definition frontmatter gains three additive keys on `RoleConfig` (`deny_unknown_fields` stays): `write: bool` (default `false`), `env: Vec<String>` (default empty), `image: Option<String>`. `RoleRow` and `Resolved` carry them through; `HandSpec` gains `write: bool`, `image: String`, `env: Vec<String>`, `store_root: PathBuf`, `config_dir: PathBuf` (`cwd` stays as it is and keeps meaning the host cwd for the three host bodies). The default image is the constant `DEFAULT_HAND_IMAGE = "alpine:3.20"`. `check-config` output is byte-identical: no column is added. `[main]` accepts the keys and ignores them.
- The fake becomes `crates/arx/src/fake_hand.sh`, embedded with `include_str!` and passed as `sh -c <script> fake-hand <brief>`, so `$1` is the brief. It mirrors `fake_body` (`ledger.rs:251-297`) and `wait_delay` step for step: `[delay:N]` in milliseconds, default 100, during which stdin lines are collected as steers; `[stop:<q>]` prints `stop:<q>` and blocks on one stdin line; `[verdict:<t>]` overrides the default `done: <brief>`; collected steers are appended to the verdict text separated by spaces, exactly as today; `[crash]` exits 3 without a verdict (the `catch_unwind` path). Four probe directives are new: `[write:<path>=<text>]` writes `<text>` plus newline to `<path>` relative to the workdir before the delay; `[read:<path>]` appends `read:<path>=ok` or `read:<path>=fail` to the verdict after `cat <path>`; `[probe]` appends `env=<sorted comma-separated names> home=<$HOME> home_entries=<count of entries in $HOME> cwd=<pwd>`. Output lines are `stop:<q>` and `verdict:<text>`; anything else on stdout, and all of stderr, is appended by arx to `<root>/out/stdout.log` and `<root>/out/stderr.log` and so lands in the trace. Steers are written to the container's stdin as one line each. Verified live on this host: busybox `read -t 0.3` and `sleep 0.2` both work.
- The in-process `fake_body`, `wait_delay`, `extract_directive`'s use by it and `spawn_fake`'s thread closure are deleted; `BodyKind::Fake` now spawns the script in a container through `container_hand::spawn_container_hand(spec, hand, brief, delivery_tx, control_rx)`, a fourth body module beside `claude_hand.rs`, `codex_hand.rs`, `native_hand.rs`, with the same signature. `extract_directive` stays if anything else uses it; otherwise it goes with the closure.
- Two literal agent names are special-cased where `fake` is today (`main.rs:333-344`, `main.rs:382-386`): `fake` (not write-enabled) and `fake-write` (write-enabled). Neither has a definition file. Both use `DEFAULT_HAND_IMAGE` and an empty allowlist.
- Delivery on the container path is body-thread-owned and sweep-first. The thread reads stdout to EOF, forwarding each `stop:` line as `Delivery::Stop` at once and holding the `verdict:` line; on EOF it reaps `docker run`, runs the sweep, removes worktree, root and container, then sends `Delivery::Verdict { trace: Some(handle), .. }` if a verdict line was seen, else `Delivery::Killed { hand, trace: Some(handle) }`. `Control::Kill` becomes `docker kill <name>`; the reader then reaches EOF and the same path runs, so a killed hand's diff is swept before its stub lands in main's window (`6aab1d24`). `Control::Steer(text)` writes `text` plus newline to the container's stdin.
- `Delivery` widens additively: `Verdict` gains `bytes: Option<u64>`, `Killed` gains `trace: Option<String>` and `bytes: Option<u64>`; every existing constructor takes `None`, every pattern takes `..`. `SpawnLedger::kill` keeps marking the hand terminal and refusing a second kill, but for `BodyKind::Fake` it no longer writes the killed row or pushes `Delivery::Killed` itself: it sends `Control::Kill` and the row lands when the thread's `Killed` delivery is drained. For the three host bodies the ledger's synchronous row and push stay exactly as they are; their kill arms are not edited. The `killed` ledger row gains `trace` when the delivery carries one. `format_delivery` renders a killed delivery with a trace as `[hand <id> killed] exit: killed (trace: <handle>)` and without one exactly as today.
- The trace handle is `threads/<thread>.<hand>`, a directory under `threads_dir`, relative to `config_dir` like the host bodies' `threads/<thread>.<hand>.jsonl`. It holds `trace.md` — YAML front matter `hand`, `agent`, `thread`, `image`, `container`, `exit` (the integer status, or `killed` when a kill was signalled), `write`, `base` (the worktree base sha, write-enabled only), `paths` (a list of `{path, bytes}` for every file the sweep wrote, `worktree.diff` and `out/...` entries) — followed by one body line naming the producing body kind; `worktree.diff` (write-enabled only) produced by `git -C <worktree> add -A` then `git -C <worktree> diff --cached --binary HEAD`, so untracked files, deletions and binaries are all in it; `out/`, a verbatim copy of `<root>/out`. Nothing from `home/` is swept in this card. No hashes: `7e5b09d7`'s shas wait for L3-03 rather than pulling a hashing crate in here.
- `Event::Delivered` gains two additive optional fields, `trace: Option<String>` and `bytes: Option<u64>` (`skip_serializing_if = "Option::is_none"`), filled on the container path with the handle and the sweep's total bytes. No new event kind; `KINDS` stays at 17.
- The stub sidecar's `hand:dispatch:<agent>:<brief>` grammar and the `dispatch` tool args are untouched; `fake-write` is just another agent name through them.
- `crates/arx/tests/claude_main.rs` keeps its 49 tests, names, order and assertions. The four L1-07 tests (`three_dispatches_keep_main_turning_and_verdicts_land_at_boundaries`, `steer_reaches_a_running_fake`, `kill_removes_the_hand_and_injects_the_stub`, `stop_lands_as_a_mechanical_request_and_the_answer_releases_it`) now run the fake in a container. The one permitted edit: an assertion that compares an injection for byte equality may be widened to `starts_with`/`contains` of the same text, because container deliveries carry `(trace: …)`. The runner lists every such line.
- `fresh_run_fixture_with_gate` makes `<workspace>/run` a git repository with one empty commit (`git init -q`, `git -c user.name=arx -c user.email=arx@localhost commit -q --allow-empty -m init`), so `rev-parse --show-toplevel` and `worktree add` work in every workspace. The engine's nested `store/.git` is untouched by that.
- Tests that start containers need the Docker daemon; there is no skip and no feature flag. This host has Docker 29.7.2, the owner in the `docker` group, `alpine:3.20` pulled.
- Codex gate: behaviour-changing diff, the gate runs. The provider limit is in force until 2026-09-07 08:38: one attempt, `gate_run: no` with the reason, and the reviewer gates on brief conformance, as the last three cards did.

## Chosen without a grill

- **The fake becomes a shell script in the binary.** The card says "proven with L1-07's fake hand", and the fake has no process boundary to contain. A script embedded via `include_str!` needs no path resolution, no Node, no image build, and keeps the 12 ledger tests and the 4 claude_main tests meaning what they meant. Rejected: keeping the closure and containerising something else (the card's proof would then be of a different hand); a second `BodyKind` for a "container fake" beside the in-process one (two adapters at one seam, the deletion test fails for the closure).
- **`docker` CLI, not a crate.** Every foreign process in this crate is `Command::new`; a Docker API crate would be a second way to drive one tool, plus a dependency the owner did not ask for. Rejected: `bollard`.
- **Hand roots under the system temp dir, not inside the repository.** A worktree inside the target tree would need every project's `.gitignore` to carry an arx line, and a read-only hand mounting the live tree would see sibling hands' homes — where L2-08 puts a credential. Outside the tree, only the store needs masking. The root path rides in the spawn row so nothing is hidden. Rejected: `<config_dir>/hands/` with a second tmpfs mask; a worktree under `.git/`.
- **Read-only hands mount the live tree, write-enabled hands get a worktree at HEAD.** `ebe94e38` says a worktree only when write-enabled; a tracing hand wants the owner's uncommitted state, which a fresh worktree loses. `068d4cbf`'s ".env rides in on the mount" only makes sense for the live tree. Rejected: a read-only worktree for everyone.
- **The store is masked, not just unmounted.** When the store root sits inside the repository (this repository's own `store/` is the standing case, the L2-05 owner item), "never mounted" is not enough: the live tree carries it and a worktree carries the tracked copy. An empty read-only tmpfs over that path makes `e79bed85`'s "the container never sees a claim file" hold structurally. Rejected: refusing to dispatch when the store lies inside the tree (would refuse every dispatch in this repository); leaving it to the migration item.
- **`--user uid:gid` and `HOME=/hand/home`.** Files a root container writes into a bind mount are root-owned on the host and `git worktree remove` then fails for the owner. Running as the arx user fixes that; `HOME` must then be set explicitly because the uid has no passwd entry in the image. "No home" reads as: the host home is never mounted and the container's home is an empty directory arx created for this hand. Rejected: root in the container; `--tmpfs /hand/home` (L2-08 cannot pre-populate a tmpfs with a credential).
- **The body thread owns the killed delivery on the container path; the host bodies keep the ledger's synchronous one.** The sweep must precede anything entering main's window (`6aab1d24`), and only the thread knows when the container is dead. Rewriting the three host bodies' kill arms to the same shape is L2-08/L2-09/L2-11 work, when their trace capture moves into the container anyway. Rejected: one kill path for all four bodies now (touches three adapters for no proof this card makes).
- **`Delivered` grows fields; no `sweep` event kind.** `4e10940c` wants archive growth as an instrumentation line; the delivery already is that line. A new kind would move `KINDS` and every count that locks it. Rejected: `Event::Sweep`.
- **`fake` and `fake-write`, two names.** The write axis is structural per definition (`ebe94e38` b) and must not come from the brief; the fake has no definition file, so the name carries the axis. Rejected: a `[write-enabled]` directive; an `agents/fake.md` with `body: fake` (would put `fake` into the `Body` enum and `check-config`).
- **No hashes in the trace index.** `7e5b09d7` lists shas; computing them means a `sha2` dependency or a hand-rolled digest. L3-03 formalises the sweep and can add them with the crate. Byte counts satisfy `4e10940c`. Rejected: `sha2` now.
- **Network left at Docker's default.** No ruling cuts network; the real bodies need their provider APIs. Rejected: `--network none` for the fake alone (a difference between the proof and the real thing).
- **Docker-dependent tests with no skip.** A skipped test is a green light for a runtime that does not run. Rejected: `#[ignore]` or a `docker`-present guard.
