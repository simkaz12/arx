## Problem / Solution

The harness writes two kinds of record today and reads neither back as counts. The transcript log carries turn, system, usage and gate rows through one `Line` struct; L1-07's ledger carries spawn, dispatch, steer, killed, verdict and stop rows through its own file. D09 ruled the evidence base as harness-authored event lines in the thread's transcript log, one shape per event, read by the owner as counts, feeding four policy constants: the admission threshold, the checkpoint token-delta, the reset reserve and the occupancy nudge. None of those lines exist, there is no reader, and the nudge, the one constant whose emitter has no layer-3 home, is not implemented anywhere.

This card ships the event vocabulary as one enum, the writer as a method on the transcript log, the reader as `arx events`, the dispatch lifecycle events emitted at main's call sites, and the nudge live: a per-thread latch, the operator notice, one line in main's window, and a per-hand check at delivery. The emitters for admission, pull, echo, rewind, checkpoint, reset, miss, floor and orientation land with L3-01, L3-02 and L2-06; here they are kinds with shapes, emitted only by tests.

## Decisions locked

- The event writer lives in the transcript log. `crates/arx/src/events.rs` defines `Event`, an internally tagged enum whose tag is `kind`; `TranscriptLog::append_event(&Event)` writes it as one JSON line through the same single-buffer path as every other row. The dispatch lifecycle events are emitted into the transcript at main's call sites in `main.rs`, where the gate row is already written. L1-07's ledger and its `<thread>.ledger.jsonl` are not edited; the ledger stays the operational record that `steer` and `kill` resolve hands through, and the same hand and agent appear in both files. (Grill Q1, option a.)
- The gate row folds into the enum as `Event::Gate { tool, verdict }`. `append_gate` keeps its signature and delegates. The bytes on disk are identical: `{"kind":"gate","tool":"save","verdict":"allow"}`, tag first, fields in declaration order. The L1-close predicates match on those bytes and are the regression test.
- Rows are flat, `kind` at the top level, as every row is today. The reader groups by that field.
- The nudge emitter is live in this card. (Grill Q2.) The check runs in the run loop after each usage row is appended; main's occupancy is the sum of `input_tokens`, `cache_creation_input_tokens` and `cache_read_input_tokens` from that row, the same three fields `arx gauge` sums today, moved into one helper both call. On the first crossing in a thread: one `nudge` event, one operator notice, and the window line armed. Said once per thread: the latch is recovered on reopen by scanning the transcript for an existing main-seat `nudge` event. Nothing is killed.
- The window line rides the next inbound turn, operator or delivery, prefixed to its text before the turn row is appended, so the transcript and the sidecar carry the same text and no turn is spent on a notice. (Grill Q3, option b.) The line is `[arx] nudge: this window holds <occupancy> tokens, past the <threshold> line. No action is required.` followed by one blank line.
- The threshold lives at `[main] nudge = 120000`, an optional key on `RoleConfig`, default 120_000 when absent. (Grill Q4, option a.) `check-config`'s printed table does not change.
- A hand crossing the line is judged once, at delivery, from the usage its verdict carries. `Delivery::Verdict { usage: Some(u), .. }` with occupancy at or past the threshold emits `nudge` with `seat: "hand"` and the hand id, plus an operator notice, no window line, no kill. A verdict without usage emits nothing.
- The kinds, seventeen, flat fields, all strings unless noted. Emitted by this card at a call site: `gate { tool, verdict }`; `spawn { hand, agent, role }` after `ledger.dispatch` succeeds; `steer { hand }`, `tap { hand }`, `kill { hand }` after the matching ledger call succeeds; `delivered { hand, outcome }` in the delivery loop with `outcome` one of `verdict`, `stop`, `killed`; `nudge { seat, hand?, occupancy: u64, threshold: u64 }` with `seat` one of `main`, `hand` and `hand` present only for the hand seat. Emitted only by tests until their cards land: `wall { hand, tool }` the permission-wall stop (L2-08, L2-09); `admission { tool, outcome, bytes: u64, handle? }` with `outcome` one of `inline`, `externalized` (L3-01); `pull { handle, path }` and `echo { handle }` per D11's naming, a pull a read whose source path is under the trace root, an echo a whole-file pull answered with the handle it asked for (L3-01); `rewind { tokens_cut: u64 }`, `checkpoint { check, delta: u64 }` with `check` one of `pass`, `fail` (L2-06), `reset { phase, check? }` with `phase` one of `armed`, `fired`, `miss { size: u64 }` per `3a5aefb6`, `floor { overshoot: u64 }` the distance past the reserve per L3-02's done-when, `orientation { verdict }` with `verdict` one of `fine`, `thin`, `wrong` per `b03f77fc` (L3-02). The D09 chain "stop, correction, continue or kill" is read from the log as `delivered { outcome: stop }` followed by `steer` or `kill` on the same hand, so no separate stop kind exists.
- `arx events [--path ./arx.toml] [thread]`, thread defaulting to `main`, resolving the workspace root exactly as `arx gauge` does. Output: a table `kind  count` over every row kind in the file, turn, system and usage included, sorted by kind name; a blank line; then for each event kind present, in the same order, a heading line `## <kind> (<n>)` and one line per row `- field=value field=value` in declaration order, optional fields omitted when absent. A row whose kind is an event kind but fails to parse as that event is a `TranscriptError`, never skipped.
- `TranscriptLog` gains a reader `events(root, thread) -> Result<Vec<Event>, TranscriptError>` over the committed prefix, skipping turn, system and usage rows, erroring on a malformed event row. `Line` keeps parsing every row for `resolve`, `last_usage` and `recover_next_turn`; it has no `deny_unknown_fields`, so event fields are ignored there. If it does have one, STOP and report.
- Harness untouched outside the named files: `crates/arx-engine`, `sidecar/claude-main.mjs`, `arx.toml`, the root `.gitignore`, the live `store/`, `ledger.rs`, `terminal.rs`. The stub sidecar under `crates/arx/tests/fixtures/stub-sidecar/` may gain one environment variable if Scope 3 needs it (see there).
- Prose rule: everything written passes `~/.claude/skills/unslop/SKILL.md`; read it by path before writing any doc comment or the card paragraph. No inline comments beyond doc comments on public items.
