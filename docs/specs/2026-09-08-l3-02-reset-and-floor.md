Ruled by D15 (`d65f8fe1` a reset fires against a reserve sized to the ritual, the harness arms and tells the operator, the operator fires, the harness fires alone only at the floor; `18fec68a` the ritual is authoring, truth-check, mechanical check, and an attending operator sees the object before teardown and can amend it, an unattended fire tears down and shows the object at next contact; `253334ad` the probe is the respawned main's first turn, a mandated orientation report surfaced to the operator, the transcript log on disk is the repair path; `e2b0ceb2` rewind-to-fit, native only), D16 (`952d3b69` under a CLI body reset is kill-and-respawn, a fresh session with no resume, the state object as orientation, no rewind; `c474a7f4` arx's reserve arms below the body's compaction threshold, which arx pushes above its own limit through `CLAUDE_CODE_AUTO_COMPACT_WINDOW`), `31a20ff6` the CLI-main floor: a ContextWindowExceeded during the ritual kills and respawns from the last checkpoint's state object plus the transcript handle, logged as its own event carrying how far past the last checkpoint the window had grown, the transcript handle alone when no checkpoint exists, D14 (`8b9f41ae` the native ladder, the shape one body out), `1e27032c` reset has no digest step, `adec3734` verdicts land after the orientation turn, `06f9676e` the checkpoint ritual as landed in L2-06b, `d5e60f47` the harness never moves its own constants. No grill: the overnight rule (2026-09-04). The two questions the L2-06 split routed here — whether a reset respawns the sidecar child or the whole binary, and what "first step boundary" means under a CLI main — are answered under "Chosen without a grill".

## Problem / Solution

Nothing ends a window. `arx run` spawns one sidecar child and drives it until the operator leaves or something fails; every failure kills the child and exits the binary. The checkpoint ritual writes state objects, but nothing reads one back at spawn, no reserve is configured, `reset`, `floor` and `orientation` have no emitter, and the body's compaction window is set to a million tokens with nothing arx-side below it. A window that fills dies with its hands.

After this card, main's window has a ceiling and a reserve in `[main]`. Crossing the ceiling minus the reserve arms once: a `reset` event and a terminal line telling the operator to type `/reset`. `/reset` runs the checkpoint ritual as the outgoing main's last act, shows the object, takes one line to confirm or carry a note, then kills the sidecar child and spawns a fresh one in place: the ledger, the transcript, the gate and the terminal survive, the system prompt is recomposed from the store, and the new main's first turn is a harness prompt carrying the state object and the transcript path, its reply shown before the operator types again. At the ceiling the harness does the same without waiting. When the body rejects a ritual turn because the window is full, or the ritual abandons after two rounds, the floor runs: `floor` carries how far the window had grown past the last checkpoint, and the respawn orients from the latest state object on disk plus the transcript handle, or from the transcript alone.

## Decisions locked

- `[main] window` is the ceiling arx holds the body to, default 800,000 tokens; `[main] reserve` the room below it, default 16,000. Arm at `window - reserve`, harness fire at `window`. Both zero-refused; `reserve >= window` refused; for a claude-code main `window >= 900_000` refused with `main: window must stay below 900000; the body compacts near 967k of the 1M compaction window arx sets`. `CLAUDE_CODE_AUTO_COMPACT_WINDOW` stays at `1000000` on the child.
- Occupancy is `transcript::occupancy` of the turn's usage row, the number the nudge and the checkpoint clock already use. Arming happens once per window, checked after every turn.
- Reset respawns the sidecar child, never the binary. `ClaudeCodeMain::respawn` kills and reaps the current child and starts a new one inside the same shared handle, so every clone drives the new child. `SpawnLedger`, `TranscriptLog`, gate, terminal, `pending_drains`, `proposals` are untouched; hands in flight run on.
- The ritual is L2-06b's `run_checkpoint_ritual`, unchanged in its prompts and its two rounds; a reset's state object is the next checkpoint file. The reset adds what happens around it.
- Operator surface after a passed ritual on an operator fire: the object body on the terminal, then `[arx] state object <n> above. ok to tear down and respawn; any other line rides into the new main's first turn as an operator note.` One line is read. `ok` or empty proceeds; anything else becomes `Operator note: <line>` at the end of the orientation prompt. The checkpoint file is never touched after its write.
- Harness fire at the ceiling: no confirmation; the object is printed with `[arx] reset fired at the window ceiling: state object <n> written and shown below; respawning.`
- Floor: `Event::Floor { overshoot }` with `overshoot = last_occupancy - checkpoint.base` (the occupancy growth since the last checkpoint passed in this window, the whole window when none did). Taken when a ritual turn fails with `ClaudeCodeError::ContextWindowExceeded`, and when the ritual abandons after two rounds inside a reset. Notice: `[arx] floor: the window grew <d> tokens past the last checkpoint and the reset ritual could not complete; respawning from checkpoint <n>` or `… respawning from the transcript alone`.
- An ordinary turn that fails with `ContextWindowExceeded` takes the floor path too; every other adapter failure stays fatal as today.
- `ContextWindowExceeded` is classified from the sidecar's `fatal` message, case-insensitive, on any of `prompt is too long`, `tokens > `, `context window`, `context_length_exceeded`, `too many tokens`. The real string from the Agent SDK is unverified; the matcher is wide and the frontier note carries the gap.
- Respawn: `compose_system_prompt` runs again (grounding and the quarantine listing re-read), `append_system` writes a second `system` row, `Nudge.said`, `Checkpoint.base`, `Checkpoint.last_occupancy` and the arm flag return to zero, `last_handle.turn` keeps counting.
- Orientation prompt, exact. With an object: `[arx] this window is a respawn after reset in thread <thread>. Your predecessor's state object, checkpoint <n>, is below; the transcript is at threads/<thread>.jsonl, turns 1 to <t>, readable with read_file. Report in a few lines what you can resume from the object and what you cannot determine, then stop; the operator reads this before typing.` then a blank line and the object body. On the floor with an object, after the first sentence: `The reset ritual could not complete: the window had grown <d> tokens past checkpoint <n>, so turns <k> to <t> are not in the object.` where `k` is the checkpoint header's turn plus one. Without an object: `[arx] this window is a respawn after reset in thread <thread>. No state object exists for this thread; orient from the transcript at threads/<thread>.jsonl, turns 1 to <t>, readable with read_file. Report in a few lines what you can determine from it and what you cannot, then stop; the operator reads this before typing.` An operator note, when given, is the last line.
- Events: `Reset { phase: "armed", check: None }` at arming; `Reset { phase: "fired", check: Some("operator" | "harness") }` when the ritual starts; `Reset { phase: "respawned", check: Some("checkpoint <n>" | "transcript") }` after the new child is ready; `Orientation { verdict: "reported" | "empty" }` after the orientation reply, `empty` when the reply is blank. No shape changes; `every_kind()` untouched.
- Deliveries are pumped after the orientation turn, never between the ritual's turns or during teardown (`adec3734`).
- `/reset` is accepted at any time, armed or not.

## Chosen without a grill

1. Reset respawns the sidecar child inside the same adapter handle, not the binary: the ledger with hands in flight, the transcript, the gate and the terminal live in Rust and must survive; a binary respawn would orphan running containers and lose the ledger. Alternative rejected: re-exec `arx run` with a resume marker.
2. "First step boundary" under a CLI main is the turn boundary: arx sees turn ends, not tool steps, so deliveries land after the orientation turn's reply, which is the first boundary the harness owns.
3. `window` and `reserve` under `[main]` with defaults 800k and 16k; the ceiling refused at or above 900k for a claude-code main because R01 measured the body compacting near 967k of its 1M window. Alternative rejected: no default, leaving an unattended thread able to die without a state object.
4. The reset's state object is the next checkpoint file, written by the unchanged L2-06b ritual. Alternative rejected: a separate `reset.md`, a second grammar for the same object.
5. The amendment is an operator note carried in the orientation prompt, the checked file untouched, because `write_checked` never overwrites and a note is not a probe.
6. A ritual that abandons after two rounds inside a reset takes the floor path rather than leaving the window standing; the operator asked for a reset, and at the ceiling there is no window to stand in.
7. An ordinary turn rejected for a full window takes the floor path too; nothing else catches it once the body's compaction is pushed above arx.
8. The floor's distance is `last_occupancy - checkpoint.base`, the harness's own accounting, not a parse of the body's error numbers.
9. `Reset.check` carries the fire source and the respawn source; the field exists and the shape cannot change.
10. The orientation verdict is `reported` or `empty`; grading prose mechanically is not on the table, and the report itself is a transcript row.
11. `/reset` is accepted before arming.
12. The context-window matcher is five substrings; the real SDK string is unverified and carried as a finding.
13. Occupancy restarts at zero in the respawned child, as L2-06b ruled for a fresh `arx run`.
14. The stub's rejection trigger counts authoring prompts, so a test can pass one checkpoint and reject the next.
