## Problem / Solution

`anthropic.rs` is a stub that returns a Fatal naming L2-10. A definition with `provider: <anthropic row>` dispatches a hand that fails on its first call. Every other piece of the native seam is real.

This card replaces the stub with the adapter: `POST {base_url}/v1/messages` with `x-api-key`, `anthropic-version: 2023-06-01` and `content-type: application/json`, `stream: true`, the system prompt as the top-level `system` field, messages translated from arx's `Message`/`ContentBlock` shapes into Anthropic's (`tool_use` and `tool_result` blocks, tool results as `user` messages), tools translated into `input_schema` definitions, `max_tokens` fixed. The SSE event sequence is assembled inside the adapter into the same `Chunk` stream every consumer already reads: text deltas as `Content(Text)`, `tool_use` blocks accumulated from `input_json_delta` fragments into one `ToolCall` at `content_block_stop`, `thinking` blocks dropped, `message_delta`'s `stop_reason` mapped to the termination enum and its `usage` captured, `message_stop` ending the stream. Errors go through L2-10b's classes: 429 and 529 Transient with `retry-after`, 500-series Transient, a 400 whose body says the prompt is too long a ContextWindowExceeded with the overshoot parsed from "N tokens > M maximum", the rest Fatal; a mid-stream `error` event is Fatal with the vendor's message. The API key is redacted from every error text the way the OpenAI-compatible adapter already does. `build_provider`'s `Anthropic` arm returns it wrapped in `Retrying`.

## Chosen without a grill

- **`max_tokens` fixed at 8192.** Anthropic requires the field; a per-definition knob has nothing to size it against yet and a `MaxTokens` termination already continues by taking the next step. Rejected: a `max_tokens` key on the definition (a knob before its first use).
- **Consecutive tool results merged into one user message.** Anthropic's API rejects consecutive same-role messages; the loop appends one `Role::Tool` message per result. Merging at the wire keeps the `Window` shape ruled in L2-10a. Rejected: changing the loop to batch results (a wire quirk leaking into the loop).
- **Thinking blocks dropped, not surfaced.** The loop reads text and tool calls; thinking is Anthropic's own bookkeeping (`72bfc6e9`) and re-sending it needs signatures the `Message` type does not carry. Rejected: a `Thinking` content block on the seam.
- **`stop_sequence` as EndTurn.** arx sets no stop sequences; the vendor value cannot occur, and `48af6ac7` dropped it from the enum. Rejected: a Refusal for it.
- **Usage normalised to the Anthropic field names the reader already sums.** The `usage` object the adapter yields carries the four names `transcript::occupancy` reads first; no new occupancy branch. Rejected: a vendor-specific usage shape with a third `occupancy` branch.
- **One fake server with a shape flag.** The listener, the SSE pacing and the stall script are identical; only the recorded headers differ (the listener never routes on the path). Rejected: a second copy of the listener.
- **No merging of consecutive tool results.** The vendor documents that consecutive same-role turns are combined; a merge in the adapter would be a second implementation of the same rule. Rejected: merging at the wire.
- **Hermetic close when no key exists.** The card says so; the subscription login is not an API key, and `~/.config/arx/env` carries only `DEEPSEEK_API_KEY` today. Rejected: blocking the card on a key the owner has not chosen to add.
