## Problem / Solution

The claude-code hand still runs on the host. `claude -p` inherits arx's whole environment and `HOME`, runs in `config_dir`, and arx reads its session file off the host's `~/.claude/projects` after it exits. L2-07 built the container the hand is meant to live in, but its `build_argv` has one real arm, the fake's, its stdout reader speaks the fake's `stop:`/`verdict:` grammar, its sweep designates `out/` and the worktree diff and nothing under `home/`, and nothing puts a credential anywhere.

This card moves the claude-code body into that container and clamps it. `BodyKind::ClaudeCode` takes the container path in `SpawnLedger::dispatch`, with the host path in `claude_hand.rs` deleted. Before the container starts, arx writes the owner's Claude Code OAuth credential — the `claudeAiOauth` object alone — to `<root>/home/.claude/.credentials.json`, mode 600, off every path the sweep designates. The image is the definition's `image` key, built from a Dockerfile this card ships (`node:22` plus the pinned npm package). The argv is L1-08's plus the clamp: the definition's `tools` allowlist becomes `--allowedTools`, its complement against the known tool set becomes `--disallowedTools`, the write tools are struck from a hand that is not write-enabled, and the permission mode is `default`, so a tool outside the clamp is not in the model's schema at all and a shortfall comes back as the verdict text. The brief goes in on stdin, verbatim. Stdout is one JSON object, parsed by the same `build_verdict_text` L1-08 wrote. At teardown the sweep lifts the session `.jsonl` out of `<root>/home/.claude/projects/*/` into the trace directory as `session.jsonl` before the root is removed, so the raw transcript is on disk under the session on return. `permission_denials` in the result, when present, become `Event::Wall` rows. The stub `claude` the tests use becomes a tiny image; the three L1-08 tests keep their names and their meaning with their file-shape assertions re-pointed at the trace directory.

## Chosen without a grill

- **Credential file, not `CLAUDE_CODE_OAUTH_TOKEN` or an API key.** `068d4cbf` names Claude Code's credential as the mandatory entry and puts it off the designated paths; a token in `-e` is visible to `docker inspect` and would need `claude setup-token` run by the owner; an API key is a different account. Only the `claudeAiOauth` object is copied because the host file also carries an unrelated `mcpOAuth` block. Rejected: bind-mounting the host `~/.claude` (the whole host state, and `e79bed85`'s reasoning against mounts); the token env.
- **Both flags, `--allowedTools` and `--disallowedTools`, permission mode `default`.** `ebe94e38` b wants the model never to see a struck tool, which only `--disallowedTools` does; `--allowedTools` is what lets the tools it does have run without a headless prompt; `default` keeps Claude Code's own gate in force for anything neither list names (`96d1ad3a`). Rejected: `bypassPermissions` (no gate inside, and Claude Code refuses it under some uids); `--allowedTools` alone (the post-hoc refusal shape the ruling rejects).
- **The write axis strikes the write tools.** `ebe94e38` c says the read/write axis is the one thing enforced structurally; the read-only mount already blocks Bash writes at the filesystem, and striking `Write`/`Edit` from the schema makes the model's view match. Rejected: relying on the mount alone (the model would call `Write`, fail, and spend turns on it).
- **`Wire::Json` reuses `build_verdict_text`.** arx already parses this body's output; an entrypoint wrapper in the image re-emitting `verdict:` lines would put arx's parsing inside an image arx does not fully own. Rejected: a wrapper script in the Dockerfile.
- **`session.jsonl` as an extra designation, the rest of `home/` untouched.** `e2e92711` puts the CC session file on the capture surface and `068d4cbf` keeps the credential off it; the two live in the same `home/`, so designation has to be by path, not by directory. Rejected: sweeping `home/` with an exclusion for `.credentials.json` (an exclusion rule, which `e2e92711` says the sweep must not need).
- **`Wall` from `permission_denials` only.** It is the one structured denial signal `claude -p` emits; a struck tool leaves no trace but the verdict text, and inventing a text heuristic would be a parser arx does not own. Rejected: grepping the verdict for "I don't have"; a `Wall` on every non-listed tool at spawn (a wall is a hit, not a fence).
- **The stub as an image, not a bind-mounted script.** The mounts are fixed by L2-07 and adding one for tests would be a test-only seam in production code; a two-line Dockerfile on `alpine:3.20` builds in a second and caches. Rejected: `FROM node:22` for the stub (a 1 GB pull for a shell script); shipping the stub inside `arx-hand-claude`.
- **`image` mandatory for claude-code definitions.** A claude-code hand on `alpine:3.20` fails at `exec` with a confusing exit; refusing at dispatch names the fix. Rejected: a compiled-in default tag (pins a version in the binary).
- **The Dockerfile is minimal and the version pinned to the host's.** One moving part; a mismatch between the host's and the container's Claude Code would show up in the live check as behaviour drift with no way to tell which side moved. Rejected: `latest`; adding `git`/`ripgrep` (`node:22` ships git; the npm package vendors ripgrep).
- **No token write-back.** If Claude Code refreshes the OAuth token inside the container, the host's copy is not updated; arx does not write to the owner's credential file. The live check records whether the file changed inside the container so the owner can judge. Rejected: copying the container's `.credentials.json` back to the host.
- **The three L1-08 tests re-pointed, four new tests in a new file.** Their names and meanings carry; their probes of `threads/main.h1.jsonl` and of the stub's host-side files cannot survive the container. Rejected: rewriting them under new names (the card says L1-08's done-check passes).
