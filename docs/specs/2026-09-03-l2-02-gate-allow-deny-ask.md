## Problem / Solution

L1-05 put the seam in: `Gate::decide(&GateCall) -> GateVerdict` with `Allow`, `Deny { reason }` and `Ask`, one adapter `AllowAll`, and the sidecar answering the Agent SDK's `canUseTool` from the verdict. Nothing behind the seam decides anything. `Ask` is turned into a deny with "ask not yet supported" before it crosses the wire, no rule exists anywhere, `arx.toml` refuses a rules table because every config struct denies unknown fields, and the gate closure in `run_turn_cycle` cannot reach the terminal or stdin, so a prompt has nowhere to land. The owner's daily posture under Claude Code, deny-only with dippy parsing every Bash command, does not exist under arx.

This card ships the real adapter: a rule table in Claude Code's own permission grammar, read from `[gate]` in `arx.toml` and from a user-tier file, evaluated in the ruled order; hook rules that run the owner's existing PreToolUse hooks unchanged, dippy first among them; deny returned to the body with its reason and logged; ask suspending the turn for a blocking operator prompt whose answer, once or always, is the gate's own return, with "always" written back to the repo file as a rule. The seam's signature does not move and the callback's type in `run_turn_cycle` is unchanged.

## Decisions locked

- **Rule grammar and files (grill Q1).** A rule is a string in Claude Code's permission grammar: `Tool` matches every call of that tool, `Tool(pattern)` matches when the pattern, a glob where `*` matches any run of characters and nothing else is special, matches the call's subject. `Tool(prefix:*)` is accepted and means `Tool(prefix*)`, so a line can be pasted from `settings.json`. Rules sit in three ordered arrays `deny`, `ask`, `allow`, plus `hooks`, under one `[gate]` table. Repo tier: `[gate]` in `arx.toml`. User tier: the same `[gate]` table in `$XDG_CONFIG_HOME/arx/gate.toml`, default `~/.config/arx/gate.toml`, overridden by the `ARX_USER_GATE` environment variable when set (tests point it inside their temp root so the owner's real file never leaks in). Both files: every array optional, defaults empty, unknown keys refused. A rule that fails to parse is a `check-config` error and an `arx run` startup error. No other rule source exists; the store never holds one (`91d75ffe`).
- **Subjects.** The pattern is matched against one string per tool: `command` for `Bash`; `file_path` for `Read`, `Edit`, `Write`, `MultiEdit`, `NotebookEdit`; `url` for `WebFetch`; `query` for `WebSearch`; `pattern` for `Grep` and `Glob`. A `Tool(pattern)` rule on any other tool, including every `mcp__*` tool, is a config error naming the tool and saying to use the bare name. A missing subject field on a call is an empty string.
- **Precedence.** The repo table is evaluated first and in full; the user table only if nothing in the repo table matched; then the default, which is allow, because the table ships empty (`799b0967`) and the L1-close script passes on an empty table. Inside a tier the order is: `deny` list, then hook denies, then exact `allow` lines, then hook asks, then the `ask` list, then the `allow` list. First match wins, nothing overrides. An exact allow line is one without `*`; it stands above the ask stage because it is the record of an answered ask (see Ask) and would be dead below it. "Not-in-surface first" is structural under the SDK: `canUseTool` fires only for tools in the surface.
- **Hook rules (grill Q2).** `hooks` is a list of command strings. Each runs once per call, in list order, through `sh -c <command>`, with the PreToolUse payload on stdin: `{"hook_event_name":"PreToolUse","session_id":<thread>,"cwd":<workspace root>,"tool_name":<tool>,"tool_input":<input>}`. Read back, in this order: exit code 2 is a deny with stderr as the reason; exit 0 with JSON on stdout carrying `hookSpecificOutput.permissionDecision` is that decision, `permissionDecisionReason` as the reason; exit 0 with the older `{"decision":"block","reason"}` is a deny and `"approve"` an allow; exit 0 with empty stdout or JSON without a decision is no opinion. Any other exit code, a timeout at five seconds, stdout that is not JSON, or a command that cannot start is a deny with reason `hook <command>: <what happened>`. A hook's allow and no-opinion both mean no opinion: hooks narrow, never widen (`64c789d0`). `updatedInput` from a hook is ignored and logged as a notice once per session; output filtering is admission's job (L3-01), which is why arx points at `dippy-hook` and not at `bashfilter-chain`. The owner's line: `hooks = ["~/.local/share/dippy/bin/dippy-hook"]`.
- **Ask (grill Q3).** When the adapter returns `Ask`, the gate closure in `run_turn_cycle` renders the prompt through the terminal seam, blocks on the next operator line, and returns the answer as the verdict, so the sidecar never sees an ask (`64c789d0`) and the turn is suspended for exactly that read (`ce46b9ea`). The prompt is `TerminalMsg::Ask { tool, subject }`, rendered as one header line `[arx] ask: <tool> <subject>` with newlines in the subject shown as `⏎` and the subject cut at 200 characters with `…`, then the line `a allow once · A allow always · d deny once · D deny always · a note may follow the key: ` with no newline, flushed. The prompt prints on a pipe as well as a TTY. The answer's first character is the key, case-sensitive; the rest, trimmed, is the note. Any other line reprints `[arx] answer with a, A, d or D` and reads again. EOF on stdin is a deny with reason `no operator answer, stdin closed`. Once means this call only. Always appends `Tool(subject)` with the exact subject, or the bare `Tool` when the tool has no subject, to the repo tier's `allow` or `deny` array, then answers this call the same way. The append edits `arx.toml` in place through a format-preserving TOML editor, creating `[gate]` when absent; comments and unrelated tables survive byte for byte. A deny's note travels to the body as the deny reason; an allow's note is logged. No session cache of once answers.
- **Every gate decision is a log line.** `Event::Gate` gains two optional fields, `by` and `reason`, both `#[serde(default, skip_serializing_if = "Option::is_none")]`, so a default allow still writes exactly `{"kind":"gate","tool":"save","verdict":"allow"}` and the locked-bytes test stands. `by` is `rule`, `hook` or `operator`; `reason` is the matching rule text with its file (`deny "Bash(git push*)" in ./arx.toml`), the hook's reason prefixed with the command, or the operator's note. An ask writes two rows: `verdict: "ask"` with its `by` and `reason`, then the answer with `by: "operator"`. A default allow writes neither field.
- **The seam.** `Gate` and `GateCall` are unchanged. `GateVerdict` is unchanged. `AllowAll` stays for tests and the native hand. The adapter is `Table` in `gate.rs`, built from the two tiers. `run_turn_cycle` takes `&mut dyn Gate` instead of `&mut AllowAll`; the `on_gate` callback type `FnMut(&GateCall) -> GateVerdict` and the sidecar protocol do not change. `claude_code.rs`'s `Ask` arm stays as the fail-safe for any caller that returns an unresolved ask.
- **Deny reaches the body.** The sidecar already answers `{behavior:'deny', message: reason}`; the reason is now the rule's, the hook's or the operator's note. A denied call never executes; the test proves it on the store: a denied `save` leaves `store/quarantine/` without a file.
- **Hands are out.** The native hand's `AllowAll` and its ask-as-deny stub stay for L2-11; `claude_hand.rs` and `codex_hand.rs` are untouched (`96d1ad3a`).
- **`check-config`.** Validates both tiers and errors on a malformed rule, a pattern on a tool without a subject, or an unreadable user file. After the roles table, one line `gate: repo deny N ask N allow N hooks N · user deny N ask N allow N hooks N`, printed only when at least one array in either tier is non-empty, so every existing fixture's output is byte-identical.
- **Harness untouched outside the named files:** `crates/arx-engine`, `ledger.rs`, `native_hand.rs`, `claude_hand.rs`, `codex_hand.rs`, `events.rs` beyond the two fields, the root `arx.toml` beyond nothing (the owner adds the `[gate]` table by hand), the live `store/`. ## Chosen without a grill

Each call the brief takes alone, flagged so the owner can veto in the spec text. None reopens a ruling.

- "Repo wins" read as the repo table evaluated in full before the user table is consulted at all. The alternative, one merged deny-then-ask-then-allow pass over both tiers, would let a user deny beat a repo allow, which is the opposite of the ruling's words.
- The exact-allow line standing above the ask stage. Under a strict deny, ask, allow order an "always allow" answer could never take effect, since the ask rule or hook that asked would match first every time; the ruling says the answer appends a line that settles the matter. Exactness is the marker of an answered ask; a wildcard allow stays below ask.
- Default allow when no rule matches. The table ships empty by ruling and layer 1 closed on allow-everything.
- The subject table above, Claude Code's own field per tool, and refusing patterns on tools without one instead of matching against serialised input.
- Hook answers of allow and no-opinion both treated as no opinion, so a hook can only narrow. Claude Code lets a hook's allow bypass its permission system; that is the widening the ruling forbids.
- Five seconds for a hook, `sh -c` as the launcher, the payload's five fields, and failure of any kind as a deny.
- The prompt text, the four keys, `⏎` for newlines and the 200-character cut.
- `ARX_USER_GATE` as the test seam for the user tier.
- `Event::Gate`'s two optional fields rather than a second event kind for the operator's answer.
- The `check-config` gate line, printed only when a tier is non-empty.
- `toml_edit` for the append, added as a dependency; if the `toml` crate already in the tree exposes a format-preserving document type, use that instead and say so.
- The done-when's scripted session lives in `tests/scripts/l2-02-gate.json`, driven by the L1-close runner's helpers from a new `tests/gate.rs`, so the layer-2 close can accumulate it.
