## Problem / Solution

The codex hand is the last body still spawned on the host. `codex_hand::run_codex_hand` runs `Command::new("codex")` with arx's whole environment and `HOME`, so it authenticates off the owner's real `~/.codex/auth.json`, reads the owner's `~/.codex/config.toml` (MCP servers, project trust, `project_doc_fallback_filenames = ["CLAUDE.md"]`) and the owner's user-level `~/.codex/AGENTS.md`, and copies its rollout off the host's `~/.codex/sessions` after exit. The judge (L1-11) rides this same path. The container runtime L2-07 built and L2-08 and L2-11 filled has placeholder arms for codex: `container_hand::build_argv` falls through to `vec!["true"]` and `Wire::from_kind` hands codex the fake's `stop:`/`verdict:` line reader.

This card moves the codex body into that container and clamps it. `BodyKind::Codex` takes the container path in `SpawnLedger::dispatch`, with the host path in `codex_hand.rs` deleted along with the private helper copies L2-08 left behind. Before the container starts, arx copies the owner's `auth.json` byte for byte to `<root>/home/.codex/auth.json`, mode 600, off every path the sweep designates. The clamp is the mount: the repository is bind-mounted read-only unless the definition is write-enabled, the store is masked, and codex's own sandbox is switched off inside the container with `--sandbox danger-full-access` because the container is the sandbox. The brief goes in on stdin, the `--json` event stream comes out on stdout through the parser `codex_hand.rs` already has, the rollout is lifted into the trace as `session.jsonl`, and the trace becomes directory-shaped like every other body's. The image is the definition's `image` key, built from a Dockerfile this card ships (`node:22` plus `@openai/codex@0.152.1`), and `image` becomes mandatory for codex definitions as it is for claude-code ones. A write attempted through a read-only mount fails inside the container and the hand's own verdict says so: that is the fail-loud contract.

## Decisions locked

- **Route.** `BodyKind::in_container()` includes `Codex`. The host arm in `ledger.rs` (`BodyKind::Codex => codex_hand::spawn_codex_hand`) is deleted; `spawn_codex_hand`, `run_codex_hand`, `codex_home`, `locate_and_copy_rollout`, and the four private copies `kill_and_reap`, `ExitOutcome`, `wait_for_exit`, `read_tail` are deleted from `codex_hand.rs`. If every kind is now in a container, `in_container()` and the non-container arm go too; if something else still calls them, keep them and say so. No host codex path remains.
- **What `codex_hand.rs` keeps.** `ARX_HAND_INSTRUCTIONS` (name, `pub(crate)` visibility and text unchanged; `native_hand.rs:16` imports it), `build_argv`, the stream parser (`parse_stream`, `handle_line`, `apply_event`, the `MAX_LINE_BYTES` and `RAW_TAIL_BYTES` bounds), `build_verdict_text` with its text rules unchanged (verdict is the last `agent_message` text verbatim on `turn_completed`; otherwise `codex exec failed — …` from `last_error`, the read error, the raw tail or the exit status, plus the stderr tail), and `find_rollout_file`, re-pointed to take the codex home directory as an argument. Whatever `container_hand.rs` needs becomes `pub(crate)`.
- **argv, in order.** `exec --json --model <spec.model> --skip-git-repo-check --sandbox danger-full-access -c instructions="<ARX_HAND_INSTRUCTIONS>" -c project_doc_max_bytes=0`. `--skip-git-repo-check` stays: the worktree's `.git` file names a host gitdir the container cannot see. No `-a`: `codex exec` hardcodes approval `never`. No `-o`, no `--output-schema` (L2-12). `container_hand::build_argv`'s codex arm is `["codex", ...codex_hand::build_argv(spec)]`.
- **The clamp.** The read/write axis is the mount L2-07 already enforces: `/hand/repo` read-only (the toplevel) when `spec.write` is false, the worktree read-write when it is true, the store masked by tmpfs either way. Codex's own Linux sandbox is off (`--sandbox danger-full-access`); a read-only hand can therefore still write under `/hand/out` and `/hand/home`, and that is accepted. A write attempted under a read-only `/hand/repo` fails with a read-only file system error inside the container, codex reports the failed command to the model, and the verdict carries it. The `tools` key is not compiled for codex: codex has no per-tool-name surface. A `tools:` list on a codex definition is ignored, as today.
- **The credential.** `prepare` reads `${CODEX_HOME:-$HOME/.codex}/auth.json` from arx's own environment, requires it to parse as a JSON object carrying either a `tokens` object or a non-null string `OPENAI_API_KEY`, and copies the file byte for byte to `<root>/home/.codex/auth.json` with mode `0600`, `.codex/` created `0700`. Missing file, unparsable JSON, or neither key → refused with `dispatch: no Codex credential at <path>; log in on the host first`, root removed, before any worktree or container exists. Only `BodyKind::Codex` gets this step. Nothing else from `~/.codex` goes in: no `config.toml`, no `AGENTS.md`, no databases, no skills. No token write-back to the host.
- **Home.** `HOME=/hand/home` is already unconditional in `ContainerSpec::args`; codex resolves its home to `$HOME/.codex` from that. `CODEX_HOME` is not set inside the container and is not forwarded from the host.
- **Wire.** A third `Wire` arm for codex: the brief is written whole to stdin and stdin is dropped (the L2-08 contract); stdout is fed to `codex_hand::parse_stream` as it arrives; stderr's tail is kept as for claude-code; `Delivery::Verdict` carries `build_verdict_text`'s text and the `turn.completed` usage object passed through verbatim. `Control::Steer` returns the mechanical refusal it returns today. `Control::Kill` is `docker kill` followed by `Delivery::Killed`, the same as the other container bodies (the host path sent nothing on kill; that asymmetry ends here).
- **Rollout lift.** After the container exits, the newest `rollout-*.jsonl` under `<root>/home/.codex/sessions/` is added to the sweep's `extra` as `session.jsonl` and lands in the trace directory as a designated path. If none is found the verdict text is suffixed ` (capture failed: no rollout under sessions/)`, as today. `auth.json` is never in `extra`.
- **Trace handle.** The codex trace is `threads/<thread>.<hand>/`, a directory with `trace.md`, `out/`, `session.jsonl` and, for a write hand, `worktree.diff`. The flat `threads/<thread>.<hand>.jsonl` handle L1-09 and L1-11 asserted is retired; this is the same reshape L2-08 made for claude-code. The judge's handle changes with it.
- **Image.** `docker/codex-hand/Dockerfile`: `FROM node:22`, `ARG CODEX_VERSION=0.152.1`, `RUN npm install -g @openai/codex@${CODEX_VERSION}`. Tag `arx-hand-codex:0.152.1`, the host's pinned version. `image` is mandatory for codex definitions at `resolve_hand_spec`, the same check and error shape as claude-code. `agents/hand-cx.md` and `agents/judge.md` get `image: arx-hand-codex:0.152.1`; the run fixtures `crates/arx/tests/fixtures/run/agents/hand-cx.md` and `judge.md` get `image: arx-codex-stub:test`. The check-config fixtures are not dispatched and get no `image` line.
- **The judge.** Rides the same path with no judge-specific code (`e652ce3a`); read-only, so its repo mount is `:ro`. L2-12 builds on this argv and this trace.
- **Test stub.** `crates/arx/tests/fixtures/bin/codex` moves to `crates/arx/tests/fixtures/codex-stub/codex` beside a Dockerfile (`FROM alpine:3.20`, `RUN apk add --no-cache bash`, `COPY codex /usr/local/bin/codex`, `chmod 755`), built on first run as `arx-codex-stub:test` by `common::ensure_codex_stub_image()` behind a `Once`, the shape of `ensure_claude_stub_image()`. The stub resolves its home as `${CODEX_HOME:-$HOME/.codex}`, writes its argv as the first line of the rollout it fabricates (`{"stub":"argv","argv":[…]}`), writes a second line reporting the credential (`{"stub":"auth","present":true|false,"mode":"600"}`), and when the brief's first line is `probe-write: <relative path>` attempts `printf l2-09 > /hand/repo/<relative path>` and puts `wrote /hand/repo/<path>` or `write refused: <error text>` in its `agent_message`. Everything else the stub emits today stays.
- **Tests.** The test fixtures plant a stub `auth.json` (`{"auth_mode":"chatgpt","tokens":{"access_token":"stub","refresh_token":"stub","id_token":"stub","account_id":"stub"},"last_refresh":"2026-09-07T00:00:00Z"}`) under a temp `CODEX_HOME` set in arx's environment, the way the claude tests plant `.credentials.json` under `CLAUDE_CONFIG_DIR`.
- **Nothing else moves.** No network flag, no resource limit, no `check-config` change, no `prompts/main.md` change (it names no handle shape), no `elapsed_ms` work (L2-15 stamps every body at the ledger).
- **Gate amendments, 2026-09-07, sanctioned by main during the codex rounds.** (1) `prepare` injects the codex credential right after the hand root is created and before `Worktree::add`, so a refused write dispatch leaves no worktree. (2) The env allowlist never forwards `HOME` or `CODEX_HOME` by name. (3) The shared `plan()` masks the credential source directory with tmpfs when it resolves beneath the repository toplevel, for both codex and claude-code sources, after canonicalising both paths; this is a shared-runtime change in `container_hand.rs`, not a claude-code path change, and the claude-code credential injection itself is untouched. Each carries a unit test in `main.rs`'s test module or an extension of `codex_in_container.rs`'s missing-credential test.

## Chosen without a grill

- `--sandbox danger-full-access` rather than `read-only`/`workspace-write` by `spec.write`. The mount is already the structural clamp (`ebe94e38`) and `codex exec` never asks. Probed after the brief was first written: Codex 0.152.1's Linux sandbox is bubblewrap, and inside this container shape `bwrap` fails with `Creating new namespace failed: Operation not permitted` under Docker's default seccomp and AppArmor, as root and as uid 1000. The `sandbox_mode = read-only` clause of `1e6ad121` cannot run in a container without `--privileged` or an unconfined seccomp profile, so the ruling was reopened in the store as `84c34f6a` before this card continued. Not a later tightening: the two are mutually exclusive.
- `auth.json` copied whole, not a sub-object. Every top-level key is auth (`auth_mode`, `OPENAI_API_KEY`, `tokens`, `last_refresh`); dropping `last_refresh` would push codex to refresh on every dispatch, which is the write-back hazard.
- The newest rollout by mtime, not the one matching `thread.started`'s id: one dispatch, one rollout, and the stub's fabricated file has no real thread id.
- `Delivery::Killed` on kill, aligning codex with the other container bodies rather than preserving the host path's silence.
- `bash` installed in the stub image rather than porting the stub to POSIX `sh`.
- `tools:` on a codex definition ignored, not refused.
- The flat `.jsonl` trace handle retired for codex and judge; the two `layer_close.rs` assertions and the four `claude_main.rs` codex tests are re-pointed, not deleted.
